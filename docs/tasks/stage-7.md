# Задачи этапа 7. Paper trading и демо-счёт

Формат тот же, что в [stage-3.md](stage-3.md). Правила — в [05-risk-and-execution.md](../05-risk-and-execution.md). **Реальный счёт на этом этапе не используется**: бот работает в режиме `paper` (виртуальные сделки по живым ценам) или `demo` (Bybit Demo Trading).

## Решения по умолчанию

| Где | Решение | Почему |
|-----|---------|--------|
| Интерфейс брокера | Синхронный (pybit синхронный, поток WS — отдельный поток); в 02 указан async — отличие осознанное, логика та же | проще для новичка и для тестов |
| Лимиты риска | Все 13 проверок из 05 в `risk/limits.py`; значения в `config/default.yaml`, раздел `limits`; ослабить их больше значений из 05 конфиг не даст | правило CLAUDE.md |
| Ликвидация | Плечо на бирже ставится равным `max_leverage` (3x) для isolated; цена ликвидации ≈ вход × (1 ∓ 1/плечо ± 0,5%); если стоп дальше половины этого расстояния — сделка отклоняется | проверка 4 из 05; с 3x почти не срабатывает |
| Корреляция | BTC и ETH в одну сторону: вторая позиция получает риск ÷ 1,5 | проверка 8 |
| Плановые события | Проверка 14 (календарь) не реализуется — необязательная | 05 |
| Состояние | SQLite `data/bot.sqlite`: сигналы, ордера (машина состояний), сделки, события, состояние риска; запись до и после каждого сетевого вызова | 05 |
| Повтор после сбоя | Ошибка сети → сначала поиск ордера по `orderLinkId`; повтор только если ордера нет; до 3 попыток с паузой 1, 2, 4 с; ошибки валидации не повторяются | 05 |
| Выход по времени и трейлинг | На закрытии свечи стратегии: трейлинг двигает стоп на бирже (`set_trading_stop`), выход по времени — рыночный `reduceOnly` | как в бэктесте |
| Reconciliation | При старте и каждые 5 минут. Позиция без стопа → стоп немедленно. Неизвестная позиция → уведомление (закрытие — только если `close_unknown: true`) | 05 |
| Kill switch | Кнопка в интерфейсе, команда `/kill` в Telegram-боте, файл `data/KILL`. Отменить ордера, закрыть позиции, остановить торговлю до ручного `/resume` | 05 |
| Уведомления | Telegram Bot API (`TG_BOT_TOKEN`, `TG_CHAT_ID`), без новых библиотек | 02 |
| Сравнение с бэктестом | Команда: бэктест той же стратегии на тех же свечах против сделок бота, сопоставление по `signal_id` | 03 |

### 7.1 Лимиты риска
`src/bot/risk/limits.py`: проверки 1–13, состояние риска (дневной убыток, просадка, серия убытков, остановка).

### 7.2 Брокер и хранилище
`src/bot/execution/broker.py` (интерфейс), `src/bot/execution/store.py` (SQLite).

### 7.3 PaperBroker
Виртуальное исполнение по живым свечам с комиссиями и проскальзыванием как в бэктесте.

### 7.4 BybitBroker (демо)
Ордера с `orderLinkId`, SL/TP на бирже, `reduceOnly`, обработка ошибок, поиск ордера перед повтором.

### 7.5 Reconciliation
`src/bot/execution/reconcile.py`.

### 7.6 Runner
`src/bot/runner/live.py`: свечи → стратегии → риск → брокер; конфиг `config/live.yaml`.

### 7.7 Уведомления и kill switch
`src/bot/notify/telegram.py`, команды `/status`, `/kill`, `/resume`.

### 7.8 Сравнение с бэктестом
`python -m bot.research.live_vs_backtest`.

### 7.9 Интерфейс: состояние бота
Вкладка «Бот»: режим, капитал, открытые позиции, события, кнопка аварийной остановки.

### 7.10 Тесты сбоев
Тесты по списку из 05 на подставных брокерах; инструкция для ручных тестов на демо.

## Как проверить на своём компьютере

См. раздел «Живая торговля» в [USER_GUIDE.md](../USER_GUIDE.md). Кратко: `uv run python -m bot.runner.live --mode paper`, затем `--mode demo`; ≥ 4 недель и ≥ 30 сделок; ручные тесты сбоев из 05.
