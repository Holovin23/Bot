# Задачи этапа 8. Минимальный реальный объём

Формат тот же, что в [stage-3.md](stage-3.md). **Код этапа написан, но выключен.** Реальный счёт включает только владелец, когда этап 7 выполнен (≥ 4 недель на демо, ≥ 30 сделок, ручные тесты сбоев из 05 пройдены, сравнение с бэктестом без необъяснённых расхождений).

## Решения по умолчанию

| Где | Решение | Почему |
|-----|---------|--------|
| Ключи | Отдельный файл `.env.live` (не в git), в нём `BYBIT_ENV=live`, `ALLOW_LIVE=true` и ключ реального счёта без права вывода | 05: «демо-ключи и реальные ключи — разные файлы» |
| Запуск | `--mode live` + ручное подтверждение при старте: ввести `LIVE` и сумму капитала с биржи | 05: «явный флаг и подтверждение при старте» |
| Риск-профиль | Раздел `live_risk` в `config/default.yaml`: риск 0,25%, 1 позиция, дневной убыток 1%, просадка 5%; код не даст поставить больше | 03, этап 8 |
| Дневной лимит | В режиме live дневной убыток — **полная остановка** (как просадка), снимается только вручную (`/resume`) | 03: «после срабатывания — только ручной перезапуск» |
| Сравнение | `python -m bot.research.live_vs_demo`: бот запускается на демо и на реальном счёте с одинаковыми стратегиями, сделки сопоставляются по `signal_id` | 03: «сравнение реального исполнения с демо» |

---

### 8.1 Профиль риска для реального счёта
`config.py`: `LiveRiskConfig`, `Config.for_live()`; `limits.py`: дневной убыток останавливает торговлю, если `daily_loss_halts`.

### 8.2 Режим live в брокере и runner
`BybitBroker.live()` — только при `BYBIT_ENV=live`, `ALLOW_LIVE=true` и подтверждении; runner `--mode live` читает `.env.live` и спрашивает подтверждение.

### 8.3 Сравнение реального исполнения с демо
`src/bot/research/live_vs_demo.py`: проскальзывание входа и выхода, частичные исполнения, результат.
