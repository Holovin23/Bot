# Задачи этапов 0 и 1

Каждую задачу можно отдать Claude Code целиком: скопировать блок «Задача» в чат. Выполнять по порядку, по одной, проверяя результат по разделу «Проверка». Общие правила — в `CLAUDE.md` и [08-ai-assisted-development.md](../08-ai-assisted-development.md).

## Этап 0. Фундамент

### 0.1 Каркас проекта

**Задача:** Создай каркас Python-проекта по `docs/02-architecture.md` (раздел «Структура репозитория») и `docs/09-start-checklist.md` (раздел «Окружение»): `pyproject.toml` для uv (Python 3.12), пакет `src/bot` с пустыми подпакетами, `tests/`, `config/default.yaml`, `.env.example`, `.gitignore` (включая `data/`, `logs/`, `.env`), настройки ruff, mypy, pytest. Добавь один тест-заглушку. Не добавляй логику.

**Проверка:** `uv sync`, `uv run pytest`, `uv run ruff check`, `uv run mypy src` проходят без ошибок. В git не попадают `.env` и `data/`.

### 0.2 Конфигурация и логирование

**Задача:** Сделай `src/bot/core/config.py`: загрузка `config/default.yaml` и `.env` в типизированные настройки (pydantic-settings), режим `BYBIT_ENV` = `demo` | `live`, по умолчанию `demo`; режим `live` требует дополнительного флага `ALLOW_LIVE=true`. Сделай `src/bot/core/logging.py`: structlog, вывод в консоль и в `logs/` с ротацией по дням. Тесты на загрузку конфига и запрет `live` без флага.

**Проверка:** тесты зелёные; секреты не печатаются в лог (проверить глазами вывод при старте).

### 0.3 Модели данных

**Задача:** Сделай `src/bot/core/models.py`: `Candle`, `Signal` (поля из `docs/02-architecture.md`, раздел «Формат сигнала»), `OrderRequest`, `Order`, `Position`, `Trade`, `Balance`. Время — UTC, `datetime` с таймзоной. У `Signal` метод построения детерминированного `signal_id`. Тесты: одинаковые входные данные дают одинаковый `signal_id`; сигнал без стопа не создаётся.

**Проверка:** тесты зелёные.

### 0.4 Проверка подключения к Bybit Demo

**Задача:** Сделай скрипт `scripts/check_connection.py` на pybit (v5): публичные данные — с основного API, приватные — с демо-домена. Скрипт печатает серверное время и разницу с локальным, баланс демо-счёта, параметры инструментов BTCUSDT и ETHUSDT (шаг цены, шаг лота, минимальный объём, максимальное плечо) и текущие комиссии аккаунта, если API их отдаёт. Затем проверь по документации Bybit, поддерживает ли Demo Trading: создание ордера с `orderLinkId`, установку стопов позиции (trading-stop), приватный WebSocket. Результат проверки запиши в `docs/09-start-checklist.md`, раздел «Что проверить в начале этапа 0». Ордера не отправляй.

**Проверка:** скрипт печатает баланс демо-счёта; раздел в 09 заполнен.

## Этап 1. Market Data

### 1.1 Хранилище

**Задача:** Сделай `src/bot/data/storage.py`: запись и чтение свечей, funding и open interest в Parquet по схеме путей из `docs/09-start-checklist.md`; чтение диапазона дат по символу и таймфрейму; дозапись без дублей (ключ — время открытия свечи). Тесты на запись, чтение, отсутствие дублей при повторной записи.

**Проверка:** тесты зелёные.

### 1.2 Загрузчик истории

**Задача:** Сделай `src/bot/data/downloader.py` и команду `uv run python -m bot.data.downloader --symbol BTCUSDT --from 2021-01-01`: загрузка 1m-свечей через `/v5/market/kline` пачками по 1000, funding через `/v5/market/funding/history`, open interest через `/v5/market/open-interest` (5 мин). Требования: соблюдать лимиты запросов, повторы при сетевых ошибках, продолжение с последней сохранённой свечи после прерывания, прогресс в консоли. Берётся только закрытая история (без текущей незакрытой свечи).

**Проверка:** загрузить один месяц и сравнить 3 случайные свечи с графиком Bybit; прервать загрузку и запустить снова — продолжает с места остановки, дублей нет.

### 1.3 Агрегация таймфреймов

**Задача:** Сделай `src/bot/data/resample.py`: из 1m-свечей собрать 5m, 15m, 1h, 4h (open — первый, high — максимум, low — минимум, close — последний, volume — сумма; время свечи — время открытия). Неполная последняя свеча периода отбрасывается. Тесты на синтетических данных с заранее посчитанным результатом.

**Проверка:** тесты зелёные; 3 случайные 1h-свечи совпадают с графиком Bybit.

### 1.4 Проверка качества данных

**Задача:** Сделай `src/bot/data/quality.py` и команду отчёта: пропуски (список интервалов), дубли, свечи с нулевым объёмом, выбросы (high/low дальше 10 ATR от close), high < low. Отчёт в консоль и в `data/reports/quality_<symbol>.md`.

**Проверка:** на полной истории отчёт сформирован; найденные пропуски совпадают с известными остановками биржи или объяснены.

### 1.5 Живой поток свечей

**Задача:** Сделай `src/bot/data/live_feed.py`: подписка на WebSocket `kline.1.<symbol>` основного API, отдача только закрытых свечей (`confirm=true`), дозапись в хранилище, автоматическое переподключение с дозагрузкой пропущенного через REST. Команда для запуска на N часов.

**Проверка:** запуск на 24 часа без пропусков в отчёте качества за этот период; при отключении сети на 5 минут пропуск после восстановления заполнен.

### 1.6 Первый взгляд на данные

**Задача:** Сделай минимальный `src/bot/app/api.py` (FastAPI) и страницу с TradingView Lightweight Charts: выбор символа и таймфрейма, свечи, EMA20/50/200 и Bollinger(20, 2). Индикаторы считаются на сервере в `src/bot/features/indicators.py` с тестами (сверка с pandas-ta на одном наборе данных). Атрибуция TradingView на странице.

**Проверка:** на `http://127.0.0.1:8000` видны свечи и индикаторы; их вид совпадает с графиком на Bybit.
