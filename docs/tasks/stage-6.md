# Задачи этапа 6. Добавление ИИ

Формат тот же, что в [stage-3.md](stage-3.md). Принципы — в [02-architecture.md](../02-architecture.md), модуль 3: **ИИ может только запретить сделку, но не создать её, не увеличить размер и не убрать стоп**; LLM только извлекает мнение автора из текста.

## Решения по умолчанию

| Где | Решение | Почему |
|-----|---------|--------|
| Режим рынка | `HIGH_VOL`: ATR% выше 90-го перцентиля за 500 свечей; иначе `TREND_UP`/`TREND_DOWN`: ADX(14) > 25 и close выше/ниже EMA50, наклон EMA50 за 10 свечей в ту же сторону; иначе `RANGE` | правила из 02, слой A |
| Метка сделки (тройной барьер) | Барьеры — стоп, тейк и выход по времени самой стратегии; метка 1, если сделка закрылась с R > 0 | метка совпадает с тем, что реально торгуется |
| Признаки | Только на закрытии сигнальной свечи: режим, ADX, RSI, ATR%, ширина BB, доходность за 1/6/24 свечи, отношение объёма к среднему, наклон EMA50, час UTC, сторона сделки | без будущего; проверка обрезкой |
| Кросс-валидация | 5 блоков по времени, «очистка» сделок, чьи интервалы пересекают блок проверки, эмбарго 1% длины истории после блока | purged k-fold из 03 |
| Модели | Логистическая регрессия (база) и LightGBM (неглубокие деревья, 200 итераций) | 03 |
| Калибровка | Isotonic по предсказаниям вне блока (out-of-fold); Brier score и таблица надёжности по 10 корзинам | 02 |
| Порог фильтра | Выбирается на in-sample по OOF: максимум Expectancy оставшихся сделок при условии, что остаётся ≥ 50% сделок | не превращать фильтр в подгонку |
| Проверка пользы | Стратегия против стратегии с фильтром на validation; фильтр считается полезным, только если Expectancy или Max DD лучше при сравнимом числе сделок | 01 |
| Telegram | Telethon (пользовательский клиент), посты в SQLite `data/bot.sqlite`, таблица `telegram_posts` | 02 |
| Claude API | Модель `claude-opus-5-5`, effort `low`, structured outputs по схеме из 02; при отказе (`stop_reason = refusal`), обрыве или неверном JSON пост помечается «не разобран» | 02 |
| Польза канала | Подписанная доходность через 4, 24, 72 ч после поста против 1000 случайных моментов; вход по open первой 1m-свечи после публикации | 03 |
| Режим → стратегия (гибрид C) | Составная стратегия: MR только в `RANGE`, TF только в `TREND_*`, Breakout в `RANGE` (сжатие); сравнивается с той же комбинацией без учёта режима | 03, п. 7 |

### 6.1 Режим рынка правилами
`src/bot/features/regime.py`, тесты с примером и проверкой обрезкой.

### 6.2 Набор данных сделок
`src/bot/analyzer/dataset.py`: признаки на закрытии сигнальной свечи и метка по итогу сделки бэктеста.

### 6.3 ML-фильтр и purged k-fold
`src/bot/analyzer/ml_filter.py`: разбиение по времени с очисткой и эмбарго, обучение логистической регрессии и LightGBM, OOF-вероятности.

### 6.4 Калибровка
`src/bot/analyzer/calibration.py`: isotonic, Brier score, таблица надёжности.

### 6.5 Фильтр в стратегии и сравнение на OOS
`src/bot/analyzer/filtered.py` (обёртка стратегии: только убирает сигналы) и команда `python -m bot.research.ml_filter`.

### 6.6 Telegram: выгрузка канала
`src/bot/analyzer/telegram_reader.py`, `src/bot/core/db.py` (SQLite).

### 6.7 Claude API: разбор постов
`src/bot/analyzer/llm_parser.py`, разметка вручную для сверки, команда разбора архива.

### 6.8 Польза канала
`src/bot/research/channel_study.py`.

### 6.9 Режим → стратегия
`src/bot/strategies/composite.py`.

### 6.10 Лента Telegram в интерфейсе
Вкладка «Telegram»: пост, время, разбор ИИ.

## Как проверить на своём компьютере

| Шаг | Команда | Что должно получиться |
|-----|---------|-----------------------|
| Тесты | `uv run pytest` | все зелёные |
| ML-фильтр | `uv run python -m bot.research.ml_filter --strategy mean_reversion --symbol BTCUSDT --timeframe 1h` | отчёт: AUC и Brier обеих моделей, таблица надёжности, выбранный порог, сравнение «без фильтра / с фильтром» на validation |
| Telegram | в `.env` `TG_API_ID`, `TG_API_HASH` (my.telegram.org); `uv run python -m bot.analyzer.telegram_reader --channel <имя_канала>` | при первом запуске Telegram спросит телефон и код; посты в `data/bot.sqlite` |
| Разметка | `uv run python -m bot.analyzer.llm_parser --label 40` | вы вручную отвечаете на вопросы по 40 постам; это эталон |
| Разбор | в `.env` `ANTHROPIC_API_KEY`; `uv run python -m bot.analyzer.llm_parser --parse --limit 20`, затем `--compare` | разборы в БД; совпадение с вашей разметкой по bias |
| Польза канала | `uv run python -m bot.research.channel_study --symbol BTCUSDT` | таблица: доходность после постов против случайных моментов |
| Гибрид | `uv run python -m bot.research.experiment --strategy composite --symbol BTCUSDT --timeframe 1h --param mode=regime` и `mode=all` | две записи в журнале для сравнения |
