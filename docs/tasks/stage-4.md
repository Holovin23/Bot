# Задачи этапа 4. Проверка на новых данных

Формат тот же, что в [stage-3.md](stage-3.md). Даты отрезков — в [09-start-checklist.md](../09-start-checklist.md), критерии OOS — в [01-goals.md](../01-goals.md), процесс — в [04-backtesting-guide.md](../04-backtesting-guide.md) (разделы 3, 6, 9).

## Решения по умолчанию

| Где | Решение | Почему |
|-----|---------|--------|
| Отрезки | IS 2021-01-01 — 2024-06-30, validation 2024-07-01 — 2025-06-30, hold-out 2025-07-01 — 2026-09-30 | 09 |
| Hold-out | Каждый запуск на hold-out записывается в `research/holdout-log.md`. Повторный запуск той же стратегии, символа и таймфрейма отказывается работать без флага `--i-know-holdout-is-burned` | «открывается один раз» |
| Walk-forward | Подбор 12 мес., проверка 3 мес., шаг 3 мес., внутри IS + validation (2021-01-01 — 2025-06-30) | 09 |
| Выбор варианта в walk-forward | Максимум «оценки плато»: средний PF варианта и его соседей по сетке (по одному шагу каждого параметра), только среди вариантов с ≥ 30 сделок на окне подбора; если таких нет — параметры по умолчанию | автоматическая версия правила «центр плато, а не максимум» |
| Разогрев на окне проверки | Бэктест начинается за 30 дней до окна, в зачёт идут сделки с сигналом внутри окна | индикаторам нужна история |
| Монте-Карло | 1000 перестановок порядка сделок, распределение Max Drawdown (медиана, 95-й перцентиль) | 04, раздел 7 |
| Критерии OOS | PF > 1,1, Expectancy > 0, Max DD не более чем в 1,5 раза хуже IS | 01 |

### 4.1 Отрезки данных и защита hold-out

**Задача:** `src/bot/research/periods.py`: отрезки из 09, проверка, что период не заходит в чужой отрезок, журнал открытий hold-out.

**Проверка:** тесты: второй запуск на hold-out без флага — ошибка.

### 4.2 Устойчивость: плато и Монте-Карло

**Задача:** `src/bot/research/robustness.py`: оценка плато по сетке параметров; Монте-Карло перестановкой сделок; статистика по списку сделок (PF, Expectancy, Max DD).

**Проверка:** тесты с примером, посчитанным вручную.

### 4.3 Walk-forward

**Задача:** `src/bot/backtest/walk_forward.py`: окна 12/3/3, подбор по сетке на окне подбора, проверка выбранного варианта на следующем окне, склейка всех окон проверки.

**Проверка:** тесты на синтетике: окна не перекрываются, сделки окна проверки только из этого окна.

### 4.4 Команда проверки

**Задача:** `uv run python -m bot.research.validate --strategy … --symbol … --timeframe … --param … --stage validation|holdout|walk-forward [--grid …]`: отчёт с метриками IS и OOS, критериями 01, Монте-Карло, проверкой на втором символе, запись в журнал экспериментов.

**Проверка:** на своих данных: отчёт открывается, критерии отмечены.

## Как проверить на своём компьютере

| Шаг | Команда | Что должно получиться |
|-----|---------|-----------------------|
| Тесты | `uv run pytest` | все зелёные |
| Validation | `uv run python -m bot.research.validate --strategy mean_reversion --symbol BTCUSDT --timeframe 1h --stage validation` | отчёт `validation.md`: IS и validation рядом, критерии ✓/✗, Монте-Карло, результат на ETHUSDT |
| Walk-forward | `... --stage walk-forward --grid adx_max=15,20,25 --grid bb_std=2,2.5` | таблица окон: какой вариант выбран на каждом окне и его результат на проверке; итог по склейке |
| Hold-out | `... --stage holdout` | один раз. Повторный запуск откажется работать. Делайте это только для стратегии, которая прошла validation и walk-forward |

Если ни одна стратегия не проходит — это результат: возвращаемся к гипотезам (новая запись в журнале), а не к подгонке параметров.
