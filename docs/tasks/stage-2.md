# Задачи этапа 2. Бэктест-движок

Формат тот же, что в [stage-0-1.md](stage-0-1.md): задачи выполняются по порядку и по одной, каждая проверяется по разделу «Проверка». Правила исполнения и издержек взяты из [04-backtesting-guide.md](../04-backtesting-guide.md) (раздел 4), значения — из [09-start-checklist.md](../09-start-checklist.md), расчёт объёма — из [05-risk-and-execution.md](../05-risk-and-execution.md).

## Принятые правила симуляции

| Ситуация | Как считаем |
|----------|-------------|
| Решение стратегии | только на закрытии свечи своего таймфрейма |
| Вход | рыночный, по открытию следующей 1m-свечи (это открытие следующей свечи таймфрейма стратегии), комиссия taker + проскальзывание |
| Стоп-лосс | рыночный при касании; если свеча открылась за стопом (гэп) — по цене открытия; проскальзывание стоп-ордера ×2 |
| Тейк-профит | рыночный при касании (так работает TP, выставленный через trading-stop), если открытие уже за тейком — по открытию; обычное проскальзывание |
| SL и TP в одной 1m-свече | сработал SL |
| Вход в той же 1m-свече | после входа по open свеча ещё может задеть стоп или тейк — это проверяется |
| Выход по времени и по сигналу стратегии | рыночный по открытию следующей свечи |
| Трейлинг-стоп | стратегия может передвинуть стоп на закрытии своей свечи, только в сторону прибыли; новый стоп действует со следующей минуты |
| Funding | в фактические моменты из истории; сумма = объём × цена (open 1m-свечи в этот момент) × ставка; лонг платит при положительной ставке, шорт получает |
| Гэп за стоп до входа | если цена входа уже за стопом, сделка не открывается |
| Позиции | одна позиция на символ, сигналы при открытой позиции игнорируются |
| Капитал для объёма | текущий баланс после закрытых сделок; стартовый 10 000 USDT |

### 2.1 Интерфейс стратегии и проверка на заглядывание вперёд

**Задача:** Сделай `src/bot/strategies/base.py`: протокол `Strategy` (`name`, `version`, `timeframe`, `params`, `required_history()`, `prepare(bars) -> признаки`, `on_bar(ctx) -> list[Signal]`, `update_stop(ctx, position) -> float | None`) и `MarketContext` (символ, свечи и признаки строго до текущей закрытой свечи включительно). Сделай `src/bot/backtest/lookahead.py`: проверка «обрезки данных» — сигналы до даты X не меняются, если удалить данные после X.

**Проверка:** тесты зелёные; специально «подглядывающая» тестовая стратегия ловится проверкой.

### 2.2 Базовая стратегия «случайные входы»

**Задача:** Сделай `src/bot/strategies/random_entry.py`: вход с заданной вероятностью на каждой свече, направление случайное, стоп k × ATR(14), тейк m × ATR, выход по времени. Случайность детерминирована (зависит от seed и времени свечи), поэтому проверка из 2.1 проходит. Нужна для проверки движка и как базовая линия на этапе 3.

**Проверка:** тесты зелёные; при одном seed результат одинаков при каждом запуске.

### 2.3 Модель издержек

**Задача:** Сделай `src/bot/backtest/costs.py`: комиссия maker/taker, цена исполнения с проскальзыванием (рыночный и стоп-ордер, вход и выход, лонг и шорт), funding за период удержания по истории ставок. Значения — из `config/default.yaml`. Функции чистые. Тесты с примерами, посчитанными вручную.

**Проверка:** тесты зелёные; один пример пересчитать на калькуляторе.

### 2.4 Расчёт объёма позиции

**Задача:** Сделай `src/bot/risk/sizing.py` по разделу «Расчёт размера позиции» из `docs/05-risk-and-execution.md`: риск в деньгах, дистанция стопа с проскальзыванием, округление вниз до шага лота, проверка минимального объёма, ограничение плеча (3x). Параметры инструментов и риска — в `config/default.yaml`. Тест на пример из документа (0,104 BTC).

**Проверка:** тесты зелёные, пример из 05 совпадает.

### 2.5 Исполнение внутри свечи

**Задача:** Сделай `src/bot/backtest/fills.py`: по 1m-свече и открытой позиции определить, сработал ли стоп или тейк, и по какой цене (правила из таблицы выше: гэпы, SL раньше TP).

**Проверка:** тесты на все случаи таблицы для лонга и шорта.

### 2.6 Движок

**Задача:** Сделай `src/bot/backtest/engine.py`: проход по 1m-свечам символа, сборка свечей таймфрейма стратегии, вызов стратегии на закрытии её свечи, вход по следующему открытию, стопы и тейки по 1m, выход по времени, трейлинг, funding, кривая капитала. Результат — список сделок (`Trade` с комиссиями, funding, проскальзыванием, причиной выхода, R) и кривая капитала.

**Проверка:** тесты на синтетике с заранее посчитанным результатом (прибыльная сделка по тейку, убыточная по стопу, гэп, выход по времени, funding).

### 2.7 Метрики

**Задача:** Сделай `src/bot/backtest/metrics.py`: метрики из раздела 6 `docs/04-backtesting-guide.md` (число сделок, Win Rate, средний выигрыш/проигрыш, Profit Factor, Expectancy в R и %, Max Drawdown и длительность, доходность, Sharpe, Sortino, Calmar, exposure, доля расходов, разбивка по годам) и buy & hold за тот же период.

**Проверка:** тесты с ручным расчётом на 4–5 сделках.

### 2.8 Отчёт и команда запуска

**Задача:** Сделай `src/bot/backtest/report.py` и команду `uv run python -m bot.backtest.report --strategy random_entry --symbol BTCUSDT --from 2021-01-01 --to 2024-06-30`: отчёт в Markdown, сделки в CSV, кривая капитала в CSV в `data/backtests/<время запуска>/`. В отчёт входят 10 случайных сделок с пошаговым расчётом (объём, цены с проскальзыванием, комиссии, funding, итог) для ручной сверки.

**Проверка:** «Готово, когда» этапа 2 из [03-implementation-plan.md](../03-implementation-plan.md): тесты на синтетике зелёные, 10 сделок из отчёта пересчитаны вручную и совпали с графиком Bybit.

## Как проверить на своём компьютере

Команды в PowerShell из `D:\Github\Bot`. Нужна загруженная история (этап 1.2).

| Шаг | Команда | Что должно получиться |
|-----|---------|-----------------------|
| Все тесты | `uv run pytest` | все зелёные |
| 2.1–2.7 | `uv run pytest tests/test_engine.py -v` | названия тестов — сценарии: тейк, стоп с гэпом, стоп и тейк в одной свече, выход по времени с funding, шорт, трейлинг; в комментариях теста каждая цифра посчитана вручную |
| 2.8 Бэктест | `uv run python -m bot.backtest.report --strategy random_entry --symbol BTCUSDT --timeframe 1h --from 2021-01-01 --to 2024-06-30` | в консоли итог, путь к `report.md` в `data\backtests\…` |
| Ручная сверка | открыть `report.md`, раздел «Сделки для ручной проверки» | пересчитать 10 сделок на калькуляторе; для 3–4 сделок найти на графике Bybit (1m, время UTC) цену открытия свечи входа и цену стопа/тейка |
| Параметры | `--param probability=0.1 --param seed=2` | другие сделки; с тем же seed результат повторяется |

Чего ждать от «случайных входов»: Profit Factor около 1 до издержек и **ниже 1 после издержек**, Expectancy немного отрицательная. Если случайные входы показывают заметную прибыль — в движке ошибка, об этом нужно сказать.
