# 02. Архитектура

## Общая схема

```
                 ┌──────────────────────────┐
  Bybit REST/WS ─►  1. Market Data          │──► Parquet / SQLite (история)
                 └────────────┬─────────────┘
                              │ свечи, funding, OI (только закрытые свечи)
                              ▼
                 ┌──────────────────────────┐
                 │  Feature Builder          │  индикаторы (EMA, BB, ATR, ADX, RSI...)
                 └──────┬─────────────┬─────┘
                        ▼             ▼
       ┌──────────────────────┐  ┌─────────────────────────────┐
       │ 2. Strategy Engine   │  │ 3. AI Market Analyzer       │
       │ MR / TF / Breakout   │  │ режим рынка, P(успех),      │◄── Telegram (текст канала)
       │ → Signal             │  │ аномалии, «пропустить»      │
       └──────────┬───────────┘  └──────────────┬──────────────┘
                  └───────────────┬─────────────┘
                                  ▼
                 ┌──────────────────────────────────┐
                 │ 4a. Risk Manager (детерминированный) │  размер, лимиты, просадка, kill switch
                 └────────────────┬─────────────────┘
                                  ▼
                 ┌──────────────────────────────────┐
                 │ 4b. Execution (Broker interface) │──► BacktestBroker | PaperBroker | BybitBroker
                 └────────────────┬─────────────────┘
                                  ▼
                       SQLite: ордера, позиции, журнал
                                  ▲
                 ┌────────────────┴─────────────────┐
                 │ 5. Web App (FastAPI + Lightweight Charts) │
                 └──────────────────────────────────┘
```

Главный принцип: **один и тот же код стратегий, анализатора и риск-менеджера работает в бэктесте, в paper-режиме и на демо-счёте.** Меняется только реализация `Broker` и источник данных. Иначе бэктест проверяет не тот код, что торгует.

Второй принцип: **ИИ может только запретить или понизить сделку, но не может её создать, увеличить размер или убрать стоп.** Риск-менеджер не знает о существовании LLM.

## Модуль 1. Market Data

**Задачи:** загрузка истории, живое обновление, хранение, проверка качества.

| Данные | Источник Bybit v5 | Хранение |
|--------|-------------------|----------|
| Свечи OHLCV | `GET /v5/market/kline` (до 1000 свечей за запрос), WS `kline.{interval}.{symbol}` | Parquet, по файлу на символ/таймфрейм/месяц |
| Funding rate | `GET /v5/market/funding/history` | Parquet |
| Open Interest | `GET /v5/market/open-interest` (интервалы от 5 мин) | Parquet |
| Тикер / цена | WS `tickers.{symbol}` | в памяти |
| Стакан (позже) | WS `orderbook.{depth}.{symbol}`; история — архивы на сайте Bybit (раздел исторических данных) | Parquet, только если нужен |
| Сделки (позже) | архивы `public.bybit.com` | Parquet |

Требования:
- Все времена в **UTC**, в миллисекундах; время свечи = время её **открытия**.
- Стратегии получают только **закрытые** свечи (`confirm=true` в WS). Использование незакрытой свечи — классический источник ложной прибыли.
- Проверка качества при каждой загрузке: пропуски, дубли, нулевой объём, выбросы цены. Отчёт о пропусках.
- Демо-счёт Bybit использует рыночные данные основной биржи, поэтому публичные данные берём с основного API, а торговые запросы шлём на демо-домен (`api-demo.bybit.com`). Перед реализацией сверить с актуальной документацией Bybit, какие эндпоинты поддерживает Demo Trading.

## Модуль 2. Strategy Engine

Каждая стратегия — класс с единым интерфейсом:

```python
class Strategy(Protocol):
    name: str
    version: str
    params: dict

    def required_history(self) -> int: ...          # сколько свечей нужно для расчёта
    def on_bar(self, ctx: MarketContext) -> list[Signal]: ...
```

Стратегия **не знает** ни баланса, ни размера позиции, ни биржи. Она только говорит: «здесь есть вход, вот где я неправа (стоп), вот цель».

### Таймфрейм на уровне стратегии

Каждая стратегия в своём конфиге задаёт рабочий таймфрейм и, при необходимости, старший таймфрейм для фильтра:

```yaml
# config/strategies/mean_reversion_btc_5m.yaml
strategy: mean_reversion
version: 1.0.0
symbol: BTCUSDT
timeframe: 5m          # 5m | 15m | 1h на старте
filter_timeframe: 1h   # например, торговать MR на 5m только когда на 1h нет тренда
params:
  bb_length: 20
  bb_std: 2.0
  adx_max: 20
```

Одна и та же стратегия может быть запущена в нескольких экземплярах с разными таймфреймами; у каждого экземпляра свой `signal_id`, своя статистика и своя строка в журнале экспериментов. Market Data хранит 1m-свечи и агрегирует из них 5m/15m/1h, поэтому добавление нового таймфрейма не требует новой загрузки.

Runner вызывает стратегию на закрытии свечи **её** таймфрейма: стратегия на 5m проверяется каждые 5 минут, на 1h — раз в час.

Важно про 5m: комиссии и проскальзывание составляют гораздо большую долю от типичного движения на 5-минутной свече, чем на часовой. Пороги из [01-goals.md](01-goals.md) для 5m-стратегий проверяются с особой строгостью (см. [06-assessment.md](06-assessment.md)).

### Формат сигнала

Предложенный формат расширен полями, без которых сигнал нельзя проверить и воспроизвести:

```json
{
  "signal_id": "tf-BTCUSDT-1h-2026-10-12T14:00:00Z",
  "created_at": "2026-10-12T15:00:00Z",
  "strategy": "trend_following",
  "strategy_version": "1.0.0",
  "symbol": "BTCUSDT",
  "timeframe": "1h",
  "side": "LONG",
  "entry_type": "MARKET",
  "entry_price": 65450,
  "stop_loss": 65000,
  "take_profit": 66300,
  "time_stop_bars": 48,
  "reason": "EMA50 > EMA200, пробой максимума 20 свечей, ADX 27",
  "features": {"adx": 27.1, "atr_pct": 0.9, "funding": 0.0001}
}
```

Значения иллюстративные. Добавлено:
- `entry_price` — без него нельзя посчитать риск и соотношение риск/прибыль (R:R). В примере выше: риск 450, цель 850, R:R ≈ 1,9.
- `signal_id` — детерминированный идентификатор; из него строится `orderLinkId`, что защищает от повторного открытия той же позиции.
- `strategy_version` и `features` — чтобы потом понять, какая версия кода и при каких условиях дала сигнал.
- `time_stop_bars` — выход по времени, если сделка «зависла».

### Стартовые стратегии (гипотезы, параметры подбираются в бэктесте)

| Стратегия | Идея | Вход (пример) | Выход | Где работает |
|-----------|------|---------------|-------|--------------|
| Mean Reversion | Цена возвращается к средней после перерастяжения | Закрытие за нижней полосой Боллинджера (20, 2), RSI < 30, ADX < 20 (нет тренда) | TP у средней линии; SL = 1,5 ATR | Боковик |
| Trend Following | Тренд продолжается | EMA50 > EMA200, откат к EMA20 и закрытие выше неё (точные правила v1 — в 09) | Трейлинг-стоп по ATR (Chandelier) | Тренд |
| Breakout | Выход из сжатия волатильности | Ширина полос Боллинджера в нижних 10% за 100 свечей, закрытие выше диапазона, объём выше среднего | SL за противоположной границей диапазона, TP 2R или трейлинг | Смена режима |

## Модуль 3. AI Market Analyzer

Работает в два слоя, второй включается только если первый доказал пользу.

**Слой A. Режим рынка (без ИИ, правила).** ADX, реализованная волатильность, наклон EMA → `TREND_UP / TREND_DOWN / RANGE / HIGH_VOL`. Это базовая линия, с которой сравнивается любой ИИ.

**Слой B. ML-фильтр сигналов.** Градиентный бустинг (LightGBM) или логистическая регрессия на признаках момента сигнала. Цель (label) — дошла ли сделка до TP раньше SL (метод тройного барьера). Выход — `p_success`, **откалиброванная** (isotonic / Platt) на отдельном отрезке данных.

**Слой C. LLM: Claude API.** Только для неструктурированного текста:
- разбор аналитических постов выбранного Telegram-канала (1–2 в день) в структуру;
- краткое объяснение текущей ситуации для интерфейса.

Поток: Telethon получает новый пост → текст и время сохраняются в SQLite как есть → Claude API возвращает JSON по заданной схеме (structured outputs, `output_config.format`) → результат сохраняется рядом с текстом и показывается в интерфейсе.

Схема ответа (пример):

```json
{
  "post_id": 1234,
  "published_at": "2026-10-12T08:15:00Z",
  "instruments": [
    {
      "symbol": "BTCUSDT",
      "bias": "BULLISH",            // BULLISH | BEARISH | NEUTRAL
      "horizon": "INTRADAY",        // INTRADAY | SWING | POSITION | UNKNOWN
      "levels": {"support": [64000], "resistance": [66500], "invalidation": 63500},
      "conviction": "MEDIUM",       // как уверенно пишет автор, а не как уверена модель
      "is_trade_call": false
    }
  ],
  "summary_ru": "Автор ждёт продолжения роста при удержании 64000",
  "parse_confidence": "HIGH"        // насколько однозначно удалось разобрать текст
}
```

Правила:
- Модель **извлекает** мнение автора, а не прогнозирует цену сама.
- Каждый разбор сохраняется с версией промпта и идентификатором модели, чтобы старые результаты можно было пересчитать.
- Ответ обрабатывается с проверкой `stop_reason` (в том числе отказа модели) и валидацией по схеме; при ошибке пост помечается «не разобран», бот продолжает работать.
- Ключ `ANTHROPIC_API_KEY` хранится в `.env`.
- Модель по умолчанию: **Claude Opus 5.5** (`claude-opus-5-5`), effort `low` или `medium`. Оценка: пост с инструкцией ≈ 2–3 тыс. входных токенов и 1–2 тыс. выходных (включая размышления модели) ≈ 3–5 центов за пост, то есть несколько долларов в месяц при 1–2 постах в день; разбор архива из ~700 постов — порядка 20–30 долларов. Цены сверять с официальной страницей Anthropic. Если захочется дешевле, Claude Haiku 5.5 (`claude-haiku-5-5`) обойдётся примерно в 40 раз дешевле; качество сравнить на 30–50 размеченных вручную постах.

Результат LLM сохраняется как ещё один признак. На решение он влияет только после того, как бэктест на исторических сообщениях канала покажет пользу (этап 6 в [03-implementation-plan.md](03-implementation-plan.md)).

Выход анализатора:

```json
{
  "signal_id": "...",
  "regime": "TREND_UP",
  "p_success": 0.58,
  "p_success_calibrated": true,
  "anomalies": ["funding_extreme"],
  "decision": "ALLOW",          // ALLOW | REDUCE | SKIP
  "explain": "funding выше 99-го перцентиля за 90 дней"
}
```

## Модуль 4a. Risk Manager

Чистые функции без сети и без ИИ, полностью покрытые тестами. Подробные правила — в [05-risk-and-execution.md](05-risk-and-execution.md).

## Модуль 4b. Execution

Интерфейс:

```python
class Broker(Protocol):
    async def place_order(self, order: OrderRequest) -> OrderResult: ...
    async def cancel_order(self, order_id: str) -> None: ...
    async def get_positions(self) -> list[Position]: ...
    async def get_open_orders(self) -> list[Order]: ...
    async def get_balance(self) -> Balance: ...
```

Реализации: `BacktestBroker` (симуляция с комиссиями и проскальзыванием), `PaperBroker` (живые цены, виртуальные сделки), `BybitBroker` (демо или реальный счёт, выбирается конфигом).

Клиент Bybit: официальная библиотека **pybit** (v5). Альтернатива — **ccxt**, если нужна мультибиржевость.

## Модуль 5. Web App

- **Backend:** FastAPI. Отдаёт свечи, индикаторы, сделки, сигналы, статус бота; управляет запуском и остановкой стратегий.
- **Графики:** [TradingView Lightweight Charts](https://github.com/tradingview/lightweight-charts) — бесплатная open-source библиотека (лицензия Apache 2.0, требует ссылку-атрибуцию TradingView). Данные и индикаторы (EMA, Bollinger, ATR, RSI) считаем сами и рисуем линиями; входы и выходы — маркерами на свечах.
  - Почему не виджет TradingView: бесплатный встраиваемый виджет показывает график TradingView, но на него нельзя нанести собственные сделки и сигналы.
  - Почему не Advanced Charts: библиотека выдаётся по заявке, для личного хобби-проекта обычно не нужна.
- **Экраны:**
  1. График: свечи + выбранные индикаторы + маркеры входов/выходов + уровни SL/TP открытых позиций.
  2. Стратегии: список, включить/выключить, параметры (только чтение во время торговли), статистика по каждой.
  3. История сделок: таблица с фильтрами, причина входа, R-результат, комиссии, funding.
  4. Бэктест: запуск, отчёт (кривая капитала, просадка, метрики, таблица сделок).
  5. Telegram: последние сообщения выбранного канала и их разбор ИИ.
  6. Состояние: подключение к API, последний тик, ошибки, кнопка аварийной остановки (kill switch).
- **API-ключи Bybit** вводятся не в браузере, а в файле `.env` (не попадает в git). Ключи только с правами на торговлю, **без права вывода**, с привязкой к IP, если возможно.

## Модуль 6. Runner (локальный запуск)

Один процесс Python на компьютере пользователя:
- подписывается на WS-свечи и при закрытии свечи прогоняет цепочку «данные → стратегии → анализатор → риск → исполнение»;
- раз в N минут сверяет позиции и ордера с биржей (reconciliation);
- раз в сутки дозагружает историю и делает резервную копию SQLite.

Если компьютер уснёт или отключится, открытые позиции защищены стоп-лоссами на стороне биржи. При старте бот сначала синхронизирует состояние с биржей и только потом начинает торговать. Для круглосуточной работы позже можно перенести тот же процесс на недорогой VPS.

## Технологический стек

| Задача | Выбор | Почему |
|--------|-------|--------|
| Язык | Python 3.12 | Лучшая экосистема для данных и ML |
| Биржа | pybit (v5) | Официальная библиотека Bybit |
| Данные | pandas / polars, pyarrow, DuckDB | Быстро, Parquet читается DuckDB напрямую |
| Индикаторы | собственные функции на numpy (+ сверка с pandas-ta / TA-Lib) | Контроль над формулами, нет утечек будущего |
| Бэктест | свой событийный движок + vectorbt для быстрых переборов | См. [04-backtesting-guide.md](04-backtesting-guide.md) |
| ML | scikit-learn, LightGBM | Стандарт для табличных данных |
| Telegram | Telethon (пользовательский клиент, чтение канала) | Бот-API не читает чужие каналы |
| LLM | Claude API, официальная библиотека `anthropic` | Structured outputs дают валидный JSON по схеме |
| БД | SQLite | Один файл, без сервера |
| Web | FastAPI + Lightweight Charts | Бесплатно, локально |
| Тесты / качество | pytest, ruff, mypy | |
| Логи и алерты | structlog + уведомления в собственный Telegram-бот | Узнавать об ошибках вне компьютера |
