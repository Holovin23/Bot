# 04. Как бэктестить стратегии

Бэктест отвечает на один вопрос: **была бы у этой стратегии прибыль после всех расходов на данных, которые я не использовал для её настройки?** Всё остальное в этом документе — способы не обмануть себя при ответе.

## 1. Сначала гипотеза, потом код

Перед тестом запишите в журнал экспериментов (`research/experiments.md`):

```
## EXP-007  Mean Reversion BTCUSDT 1h
Дата: 2026-10-20
Гипотеза: в боковике (ADX<20) закрытие за нижней полосой BB(20,2) возвращается к средней в течение 24 часов.
Почему это может работать: краткосрочные перекосы ликвидности, ликвидации лонгов.
Параметры для подбора: длина BB {14,20,30}, ширина {2,2.5}, порог ADX {15,20,25}. Всего 18 вариантов.
Критерий успеха: PF>1.2 после расходов на IS, PF>1.1 на OOS, ≥100 сделок.
Результат: ...
Решение: принять / отклонить / доработать гипотезу (НЕ параметры)
```

Число проверенных вариантов записывается всегда: оно нужно, чтобы оценить шанс случайной удачи.

## 2. Данные

- Минимум 3 года, лучше 4–5: в выборку должны попасть рост, падение и боковик (для крипты — например, 2021 рост, 2022 падение, 2023 боковик/восстановление, 2024–2025 рост).
- Таймфрейм данных мельче таймфрейма стратегии: для стратегии на 1h держите 1m или 5m свечи, чтобы корректно определить, что сработало раньше внутри часа — стоп или тейк.
- Funding-ставки за весь период: на бессрочных фьючерсах при удержании позиции днями funding может съесть заметную долю прибыли.
- Проверка пропусков: биржевые остановки, делистинг, обслуживание.

## 3. Разделение данных

```
|<-------- In-sample (60%) -------->|<- Validation (20%) ->|<- Hold-out (20%) ->|
   подбор параметров                  выбор между вариантами  один раз, в самом конце
```

- **In-sample**: здесь можно перебирать параметры.
- **Validation**: здесь сравниваем 2–3 лучших варианта, без нового перебора.
- **Hold-out**: самые свежие данные. Открываются **один раз** для финальной проверки. Если после взгляда на hold-out вы меняете стратегию, hold-out «сгорел» — нужен новый период (например, следующие месяцы paper trading).

### Walk-forward

Более надёжная схема, чем одно разделение:

```
Окно 1: [подбор 12 мес][тест 3 мес]
Окно 2:      [подбор 12 мес][тест 3 мес]
Окно 3:           [подбор 12 мес][тест 3 мес]
...
```

Результат стратегии = склейка всех тестовых отрезков. Так проверяется не только стратегия, но и сама процедура подбора параметров.

## 4. Модель исполнения и издержек

| Что | Как моделировать | Значение по умолчанию |
|-----|------------------|-----------------------|
| Вход по сигналу | По цене **открытия следующей свечи**, а не закрытия сигнальной | — |
| Комиссия taker (рыночный ордер) | % от объёма на вход и на выход | ≈ 0,055% (сверить с текущей таблицей Bybit для вашего уровня) |
| Комиссия maker (лимитный) | % от объёма, но лимитник может **не исполниться** | ≈ 0,02% |
| Проскальзывание | % к цене рыночного ордера и стопа | 0,03–0,05% для BTC/ETH; больше для альткоинов и новостей |
| Funding | Каждые 8 ч по исторической ставке, знак зависит от направления | из истории |
| SL и TP в одной свече | Считать, что сработал SL | пессимистично |
| Гэпы | Стоп исполняется по худшей из цен (стоп или открытие свечи) | — |

Пример, почему это важно: стратегия на 1h делает 3 сделки в день. Вход и выход рыночными: 2 × 0,055% + 2 × 0,04% проскальзывания ≈ 0,19% на сделку, ≈ 0,57% в день. Если средняя валовая прибыль на сделку 0,15%, стратегия убыточна, хотя без издержек выглядит прибыльной.

## 5. Главные ловушки

1. **Заглядывание в будущее (look-ahead bias).** Использование закрытия текущей свечи для входа по нему же; индикаторы, нормализованные по всему датасету; `shift` не в ту сторону; пересчёт индикатора, который «перерисовывает» прошлое. Тест: обрежьте данные на случайной дате и убедитесь, что сигналы до этой даты не изменились.
2. **Подгонка (overfitting).** Много параметров, много вариантов, мало сделок. Признаки: резкое падение на OOS, прибыль держится на 2–3 сделках, соседние значения параметров убыточны.
3. **Малая выборка.** Менее 100 сделок — статистически почти ничего. При 50 сделках и Win Rate 55% доверительный интервал примерно 41–69%.
4. **Ошибка выжившего.** Тест только на монетах, которые существуют сегодня. Для BTC/ETH не критично, для корзины альткоинов — критично.
5. **Нереалистичное исполнение.** Лимитники, которые «всегда исполнились»; объём больше, чем был в стакане.
6. **Многократный просмотр hold-out.** Каждый взгляд и последующая правка превращают hold-out в in-sample.
7. **Один режим рынка.** Тренд-стратегия, проверенная только на 2021 году, ничего не говорит о боковике.

## 6. Метрики отчёта

| Метрика | Формула / смысл | Ориентир |
|---------|-----------------|----------|
| Число сделок | | ≥ 100 |
| Win Rate | доля прибыльных | сам по себе мало значит |
| Avg Win / Avg Loss | | вместе с Win Rate |
| Profit Factor | сумма прибылей / сумма убытков | > 1,2 после расходов |
| Expectancy | WR × AvgWin − (1−WR) × AvgLoss, лучше в R | > 0,1R |
| Max Drawdown | максимальное падение капитала от пика | приемлемо для вас психологически × 2 |
| Длительность просадки | сколько времени до нового максимума | |
| Доходность после расходов | | лучше buy & hold с поправкой на риск |
| Sharpe / Sortino | доходность на единицу волатильности (годовые) | > 1 на OOS — хорошо |
| Calmar | годовая доходность / Max DD | |
| Exposure | доля времени в позиции | |
| Доля расходов | комиссии + funding + проскальзывание / валовая прибыль | < 30–40% |
| Результат по годам и по режимам | | без одного «года-спасителя» |

## 7. Проверки устойчивости

- **Сравнение со случайными входами.** Генерируйте 1000 прогонов со случайными входами той же частоты и тем же управлением выходом. Стратегия должна быть лучше, например, 95% случайных прогонов.
- **Монте-Карло по сделкам.** Перемешивайте порядок сделок 1000 раз: смотрите распределение Max Drawdown, а не одно значение.
- **Тепловая карта параметров.** Хорошая стратегия даёт «плато» прибыльности, а не одиночный пик.
- **Другой инструмент / таймфрейм.** Идея, работающая на BTC, должна хотя бы не разваливаться на ETH.
- **Удвоенные издержки.** Если стратегия умирает при комиссиях ×2, у неё нет запаса прочности.
- **Deflated Sharpe Ratio** (Bailey и López de Prado) — учитывает, сколько вариантов вы перебрали.

## 8. Инструменты

| Инструмент | Когда использовать |
|------------|--------------------|
| Свой событийный движок (`src/bot/backtest`) | Основной: тот же код стратегий, что и в живой торговле |
| vectorbt | Быстрый перебор тысяч вариантов на этапе исследования, затем перепроверка лучших в своём движке |
| backtesting.py | Быстрые прототипы и учебные эксперименты |
| Freqtrade | Готовый фреймворк с бэктестом, поддержкой Bybit, Telegram и веб-интерфейсом; полезен для сверки результатов |
| NautilusTrader | Профессиональный событийный движок, если позже понадобятся стакан и точное исполнение |

## 9. Пошаговый процесс для одной стратегии

1. Записать гипотезу в журнал (раздел 1).
2. Реализовать стратегию и юнит-тесты на сигналы (на синтетических свечах).
3. Прогнать на in-sample с издержками по умолчанию. Посмотреть 20 сделок глазами на графике.
4. Ограниченный перебор параметров (десятки вариантов, не тысячи). Построить тепловую карту.
5. Выбрать параметры из центра «плато», а не максимум.
6. Сравнить со случайными входами и buy & hold.
7. Validation → walk-forward → удвоенные издержки → другой инструмент.
8. Hold-out — один раз.
9. Записать результат и решение в журнал.
10. Если принята — paper trading и сравнение живых сделок с бэктестом за тот же период.

## 10. Чек-лист перед тем, как поверить результату

- [ ] Вход по открытию следующей свечи
- [ ] Комиссии, funding, проскальзывание включены
- [ ] SL/TP внутри свечи разрешены пессимистично
- [ ] ≥ 100 сделок
- [ ] Результат на OOS / walk-forward, а не только in-sample
- [ ] Лучше случайных входов
- [ ] Прибыль не держится на 1–3 сделках или одном годе
- [ ] Соседние параметры тоже прибыльны
- [ ] Выдерживает издержки ×2
- [ ] Число проверенных вариантов записано
- [ ] 10 сделок проверены вручную
