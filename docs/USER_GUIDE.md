# Подробная инструкция: от установки до торговли на демо-счёте

Инструкция для человека, который никогда не запускал Python-проекты. Каждый шаг написан так: **что сделать → какую команду ввести → что должно получиться**. Команды даны для Windows (PowerShell). Проект лежит в папке `D:\Github\Bot`.

> **Как вводить команды.** Откройте папку проекта в VS Code (File → Open Folder → `D:\Github\Bot`), затем откройте терминал: меню **Terminal → New Terminal**. Внизу появится окно PowerShell, строка начинается с `PS D:\Github\Bot>`. Вставьте туда команду (правый клик или `Ctrl+V`) и нажмите `Enter`. Остановить работающую команду — `Ctrl+C`.

## Часть 1. Установка (один раз)

### Шаг 1.1. Git

Git скачивает код проекта и обновления.

1. Откройте https://git-scm.com/download/win, скачайте установщик и запустите его. Все настройки можно оставить по умолчанию (кнопка Next).
2. Проверка — в новом окне PowerShell:
   ```powershell
   git --version
   ```
   Должно вывести что-то вроде `git version 2.47.0.windows.1`.

### Шаг 1.2. VS Code (редактор)

Скачайте с https://code.visualstudio.com/ и установите. В нём удобно открывать файлы настроек и запускать команды.

### Шаг 1.3. uv (Python и библиотеки)

uv сам скачает нужную версию Python (3.12) и все библиотеки проекта. В PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

**Закройте и снова откройте** терминал (иначе команда `uv` не найдётся). Проверка:

```powershell
uv --version
```

Должно вывести `uv 0.x.x`.

### Шаг 1.4. Код проекта

Если папки `D:\Github\Bot` ещё нет:

```powershell
git clone https://github.com/Holovin23/Bot.git D:\Github\Bot
cd D:\Github\Bot
```

Если папка уже есть — обновите код до последней версии:

```powershell
cd D:\Github\Bot
git checkout main
git pull
```

### Шаг 1.5. Библиотеки и проверка

```powershell
uv sync
uv run pytest
```

`uv sync` в первый раз работает 1–3 минуты. `uv run pytest` запускает все автоматические тесты; в конце должна быть строка вида `282 passed` и ни одного `failed`. Если всё зелёное — установка прошла правильно.

### Шаг 1.6. Как обновлять проект потом

Каждый раз, когда в репозитории появляется новый код:

```powershell
git checkout main
git pull
uv sync
```

## Часть 2. Ключи и пароли: где взять и куда вставить

Все секреты хранятся только в одном файле — `.env` в корне проекта. Он **не попадает в git** и никуда не отправляется.

### Шаг 2.1. Создать файл `.env`

```powershell
Copy-Item .env.example .env
code .env
```

Вторая команда откроет файл в VS Code. В нём строки вида `ИМЯ=значение`. Значение пишется сразу после `=`, без пробелов и кавычек:

```
BYBIT_API_KEY=AbCdEf123456
```

После правки сохраните файл (`Ctrl+S`).

### Шаг 2.2. Ключ демо-счёта Bybit (обязательно для демо-торговли и проверки подключения)

1. Войдите на https://www.bybit.com.
2. Переключитесь в демо-режим: нажмите на аватар (справа вверху) → **Demo Trading** (или ссылка https://www.bybit.com/en/demo-trading/). Сверху появится плашка «Demo Trading».
3. Пополните демо-счёт виртуальными деньгами, если баланс нулевой: в демо-режиме кнопка **Assets → Request demo funds / «Пополнить»**.
4. **Оставаясь в демо-режиме**, откройте аватар → **API** → **Create New Key** → **System-generated API Keys**.
5. Настройки ключа:
   - Name: любое, например `bot-demo`;
   - API Key Permissions: **Read-Write**;
   - отметьте **Contracts → Orders** и **Contracts → Positions** (Unified Trading → Trade);
   - **Withdraw (вывод) — НЕ отмечать**;
   - IP: можно оставить без привязки или указать свой статический IP.
6. Bybit покажет **API Key** и **API Secret**. Secret показывается один раз — скопируйте сразу.
7. Вставьте в `.env`:
   ```
   BYBIT_API_KEY=ваш_API_Key
   BYBIT_API_SECRET=ваш_API_Secret
   BYBIT_ENV=demo
   ALLOW_LIVE=false
   ```

> Ключ, созданный в обычном (не демо) режиме, с демо-счётом **не работает**, и наоборот.

### Шаг 2.3. Telegram-бот для уведомлений (по желанию)

Бот будет присылать вам сообщения о сделках и принимать команды `/status`, `/kill`, `/resume`.

1. В Telegram найдите **@BotFather** → `/newbot` → придумайте имя и логин (должен заканчиваться на `bot`).
2. BotFather пришлёт токен вида `1234567890:AAH...`. Вставьте:
   ```
   TG_BOT_TOKEN=1234567890:AAH...
   ```
3. Найдите своего нового бота в Telegram и напишите ему любое сообщение (например, `привет`).
4. Откройте в браузере (подставьте свой токен):
   `https://api.telegram.org/bot1234567890:AAH.../getUpdates`
   В ответе найдите `"chat":{"id":123456789` — это ваш chat id. Вставьте:
   ```
   TG_CHAT_ID=123456789
   ```

Команды бот принимает **только** из этого чата.

### Шаг 2.4. Чтение Telegram-канала с аналитикой (по желанию, этап 6)

1. Откройте https://my.telegram.org, войдите по номеру телефона (код придёт в Telegram).
2. **API development tools** → заполните App title (любое, например `bot`), Short name (`bot`), Platform — Desktop → **Create application**.
3. Скопируйте **App api_id** и **App api_hash**:
   ```
   TG_API_ID=1234567
   TG_API_HASH=0123456789abcdef0123456789abcdef
   ```

### Шаг 2.5. Ключ Claude API (по желанию, этап 6)

Нужен только для разбора постов канала.

1. https://console.anthropic.com → войдите → **Settings → Billing**: пополните баланс (разбор 1–2 постов в день стоит копейки).
2. **API Keys → Create Key** → скопируйте ключ `sk-ant-...`:
   ```
   ANTHROPIC_API_KEY=sk-ant-...
   ```

### Шаг 2.6. Проверить, что `.env` не попадёт в git

```powershell
git status
```

Файла `.env` в списке быть **не должно**. Ключи никому не пересылайте и не вставляйте в чат.

## Часть 3. Проверка подключения к Bybit

```powershell
uv run python scripts/check_connection.py
```

Эта команда **ничего не покупает и не продаёт**. Что должно быть в выводе:

| Раздел | Что значит |
|--------|-----------|
| `Серверное время … разница с локальными часами: +120 мс` | Если больше ±1000 мс — синхронизируйте часы: Параметры Windows → Время и язык → Дата и время → «Синхронизировать сейчас» |
| `BTCUSDT: шаг цены 0.1, шаг лота 0.001, мин. объём 0.001 …` | Параметры инструмента. Они должны совпадать с разделом `instruments` в `config/default.yaml` |
| `Баланс (api-demo.bybit.com) Equity: … USD` | Ключ работает, видно баланс демо-счёта |

Если вместо баланса ошибка — см. [Часть 14](#часть-14-частые-проблемы).

Ещё одна быстрая проверка, что настройки читаются и ключи не попадают в лог:

```powershell
uv run python -m bot
```

Ожидается строка `bot_started bybit_env=demo keys_loaded=True`. Самих ключей в выводе и в `logs\bot.log` нет.

## Часть 4. История цен: откуда берётся и как скачать

### Откуда бот берёт цены (и при чём тут TradingView)

- **Все цены бот скачивает напрямую с Bybit** (публичный API `api.bybit.com`, ключи для этого не нужны). Это те же свечи, что на графике Bybit BTCUSDT Perpetual.
- **TradingView здесь — только библиотека для рисования графика** (TradingView Lightweight Charts, бесплатная). Данные у TradingView бот **не берёт**, и скачивать оттуда ничего **не нужно**. Экспорт истории с сайта TradingView платный, формат другой, и такие данные бот не читает.
- Свечи хранятся на диске в `data\klines\<символ>\1m\` — файлы по месяцам (`2024-03.parquet`). Хранятся только минутные свечи; 5m, 15m, 1h, 4h собираются из них на лету.

### Шаг 4.1. Пробная загрузка (месяц)

```powershell
uv run python -m bot.data.downloader --symbol BTCUSDT --from 2026-09-01
```

Видно прогресс в процентах. В конце — `готово, новых свечей N`. В папке `data\klines\BTCUSDT\1m\` появились файлы.

Проверка глазами: откройте на Bybit график BTCUSDT Perpetual, таймфрейм 1m, и сравните 2–3 свечи (open/high/low/close) с графиком бота (Часть 5). Внизу графика Bybit можно выбрать часовой пояс.

### Шаг 4.2. Полная история (с 2021 года)

```powershell
uv run python -m bot.data.downloader
```

Скачивает для BTCUSDT и ETHUSDT: минутные свечи, ставки funding и open interest с даты `history_start` из `config/default.yaml` (2021-01-01). Это около 3 млн свечей на символ, займёт от 30 минут до пары часов. **Можно прервать** (`Ctrl+C`) и запустить снова — загрузка продолжится с места остановки. Повторный запуск докачивает только то, чего не хватает: новые свечи и пропуски в любом месте периода (например, если раньше скачались только последние дни). То же самое — вкладка «Данные» в интерфейсе.

Варианты:

```powershell
uv run python -m bot.data.downloader --symbol ETHUSDT          # только один символ
uv run python -m bot.data.downloader --from 2024-01-01          # с другой даты
uv run python -m bot.data.downloader --from 2023-01-01 --to 2023-12-31   # только за 2023 год
uv run python -m bot.data.downloader --symbol SOLUSDT           # монета, добавленная в «Данных»
uv run python -m bot.data.downloader --only klines              # только свечи
uv run python -m bot.data.downloader --only funding --only oi   # только funding и open interest
```

### Шаг 4.3. Проверка качества данных

```powershell
uv run python -m bot.data.quality
uv run python -m bot.data.quality --symbol BTCUSDT --from 2024-01-01 --to 2024-12-31
```

Отчёт: пропуски (минуты без свечей), дубликаты, подозрительные свечи. Сохраняется в `data\reports\quality_BTCUSDT.md`. Несколько коротких пропусков — это остановки биржи на обслуживание, это нормально.

### Шаг 4.4. Как держать данные свежими

Файлы с историей пополняются только когда работает что-то из этого:

| Что | Как |
|-----|-----|
| Загрузчик | `uv run python -m bot.data.downloader` — докачивает всё до текущей минуты |
| Веб-интерфейс | сам докачивает недостающие свечи для открытого символа (Часть 5) |
| Живой поток | `uv run python -m bot.data.live_feed --hours 24` — принимает каждую минуту |
| Торговый бот | `uv run python -m bot.runner.live` — принимает свечи, пока работает |

Перед бэктестами и исследованиями запустите загрузчик: интерфейс докачивает только свечи, а funding — только загрузчик.

## Часть 5. Веб-интерфейс: каждая кнопка

### Запуск

```powershell
uv run python -m bot.app.api
```

В терминале появится `Откройте http://127.0.0.1:8000`. Откройте этот адрес в браузере. Терминал не закрывайте — пока он открыт, интерфейс работает (и paper-боты, запущенные из него). Остановить — `Ctrl+C` в терминале.

Интерфейс умеет всё, что команды из Части 13: что-то — отдельными формами (график, бэктест, загрузка данных, paper-боты), остальное — во вкладке **«Команды»**.

### Вкладки сверху

| Вкладка | Что там |
|---------|---------|
| **Обзор** | Общий график: EMA 20/50/200 и Bollinger (20, 2), список всех бэктестов |
| **Trend Following**, **Daily Momentum**, **Mean Reversion**, **Composite**, **Random (база)** | Вкладка своей стратегии: график с **индикаторами этой стратегии**, бэктест, сделки, капитал, отчёт, paper-боты стратегии, описание правил. Зелёная точка у названия — работает paper-бот этой стратегии |
| **Боты** | Все paper-боты интерфейса, аварийная остановка всего, состояние бота из терминала (paper/demo/live) |
| **Данные** | Монеты: какие есть, с какого и по какое время скачаны свечи; добавить новую монету; загрузить историю за любой период |
| **Журналы** | Подробные журналы (JSON Lines) ботов и бэктестов — для разбора и для проверки ИИ |
| **Команды** | Все команды терминала с полями параметров, вывод — прямо на странице |
| **Telegram** | Посты канала и их разбор ИИ (только справочно) |

Интерфейс запоминает последнюю открытую вкладку.

### График (Обзор и вкладки стратегий)

| Элемент | Что делает |
|---------|-----------|
| **Символ**, **Таймфрейм** | Инструмент (из `config/default.yaml` и добавленные во вкладке «Данные») и таймфрейм 1m–4h. У каждой вкладки свои выбранные значения |
| **Период с … по … → Показать** | График за свой период (даты — UTC, «по» включительно). Если свечей за период нет, появится кнопка **«Загрузить с Bybit»** |
| **Сейчас** | Вернуться к живому графику (последние 1000 свечей, сам обновляется раз в минуту) |
| **Обновить** | Догрузить свежие свечи с Bybit и перерисовать |
| **Строка статуса** (справа) | Сколько свечей, время последней минутной свечи, идёт ли догрузка, «отстаёт на N мин»; «период обрезан» — если в периоде больше 20 000 свечей (возьмите таймфрейм крупнее) |
| **Легенда** | Цвета и названия всех индикаторов этой вкладки |

**Индикаторы стратегии.** На вкладке стратегии рисуется ровно то, с чем она работает, и считается тем же кодом, что в бэктесте и у бота:

| Стратегия | На графике цены | Панели под графиком |
|-----------|-----------------|---------------------|
| Trend Following | EMA 20 / 50 / 200 | ATR(14) для стопа и ATR(22) для трейлинга |
| Mean Reversion | Bollinger: верх, середина (это тейк), низ | RSI(14) с уровнями 30/70; ADX(14) с уровнем 20 (ниже — боковик) |
| Daily Momentum | Канал входа: максимум и минимум 55 свечей; канал выхода: 20 свечей | ATR(20) для стопа |
| Composite | Индикаторы обеих стратегий | Режим рынка (0 — боковик, 1 — тренд вверх, 2 — тренд вниз, 3 — высокая волатильность) и панели входящих стратегий |
| Random | — | ATR(14) |

Если изменить параметры стратегии во вкладке «Бэктест» и нажать **«Параметры → график»**, индикаторы перерисуются с новыми значениями (например, `adx_max=25` сдвинет уровень на панели ADX).

Маркеры сделок: стрелка вверх (зелёная) — вход в лонг, вниз (красная) — вход в шорт, кружок — выход (зелёный — прибыль, красный — убыток) с причиной и результатом. Для выбранной сделки: синяя линия — вход, красная пунктирная — стоп, оранжевая — стоп после трейлинга, зелёная — тейк. Колёсико — масштаб, перетаскивание — прокрутка. Время на графике — ваше локальное.

### Вкладки под графиком стратегии

| Вкладка | Что показывает и что можно сделать |
|---------|-----------------------------------|
| **Бэктест** | Форма запуска (ниже), ход выполнения и список бэктестов этой стратегии. Клик по строке — открыть бэктест на графике |
| **Сделки** | Сделки выбранного бэктеста или paper-бота. Клик по строке — переход к сделке на графике, над графиком — её описание и причина входа |
| **Капитал** | Кривая капитала выбранного бэктеста |
| **Отчёт** | Текстовый отчёт бэктеста (Часть 6) и ссылки на файлы для разбора: `trades.jsonl`, `run.json`, `skipped.jsonl` и другие |
| **Paper-боты** | Боты этой стратегии и кнопка «Создать и запустить» (ниже) |
| **Описание** | Правила стратегии и список её индикаторов |

#### Бэктест по полям

| Поле | Что значит |
|------|-----------|
| Символ и таймфрейм | Берутся с графика над формой |
| **С … по …** | Любой период (по умолчанию in-sample 2021-01-01 … 2024-06-30) |
| **догрузить данные** | Перед бэктестом скачать с Bybit недостающие минутные свечи и funding за период. Без интернета бэктест посчитается на том, что уже скачано (в журнале будет предупреждение) |
| **Параметры** | Параметры стратегии; `true`/`false` — включено/выключено. **Параметры по умолчанию** — вернуть исходные |
| **Запустить бэктест** | Под формой виден ход работы: загрузка, число свечей, итог. Готовый бэктест сам открывается на графике |

Если период задевает **hold-out** (2025-07-01 … 2026-09-30), интерфейс спросит подтверждение: hold-out — последняя честная проверка, её смотрят один раз. Если подтвердить, запуск запишется в `research\holdout-log.md`. Периоды после 2026-10-01 — обычные, без вопросов.

Одновременно идёт один бэктест. 3,5 года минутных данных — от 10 секунд до пары минут (плюс загрузка, если данных не было).

#### Paper-боты

Каждый бот — отдельный **виртуальный счёт** со своим капиталом, сделками, лимитами риска и аварийной остановкой. Можно запустить сколько угодно ботов разных стратегий, монет и таймфреймов одновременно. Стратегия, риск-менеджер и исполнение — тот же код, что в бэктесте и в `bot.runner.live --mode paper`.

1. Выберите на графике символ и таймфрейм, во вкладке «Бэктест» — параметры.
2. «Paper-боты» → укажите капитал → **Создать и запустить**. Бот скачает историю для индикаторов (до минуты) и начнёт работать: состояние «запускается» → «работает».

| Кнопка | Что делает |
|--------|-----------|
| **Стоп** / **Старт** | Остановить или снова запустить. Виртуальные позиции сохраняются и продолжаются после старта |
| **Аварийно** | Закрыть позиции бота и не открывать новых до «Возобновить» |
| **На графике** | Открыть вкладку стратегии с параметрами бота и его сделками на графике |
| **Подробно** (во вкладке «Боты») | Открытые и закрытые сделки, события, ссылка на журнал |
| **Удалить** | Убрать остановленного бота из списка. Его сделки в базе и журнал остаются |

Боты работают, пока открыт интерфейс. Если закрыть терминал с интерфейсом и запустить снова, работавшие боты запустятся сами. Демо-счёт Bybit и реальный счёт отсюда не запускаются: на одном демо-счёте несколько ботов мешали бы друг другу (позиции на бирже общие). Демо — командой из Части 9 (или вкладка «Команды» → «Бот из config/live.yaml», режим `demo`).

### Вкладка «Боты»

| Элемент | Что делает |
|---------|-----------|
| **Аварийная остановка всего** | После подтверждения закрывает позиции всех paper-ботов интерфейса и бота из терминала (через файл `data\KILL`, бот выполнит в течение минуты) |
| **Возобновить бота из терминала** | Снять остановку бота из терминала. Paper-боты интерфейса возобновляются своими кнопками |
| Таблица ботов | Состояние, капитал, открытые и закрытые сделки, итог в USDT |
| **Бот из терминала** | Состояние бота, запущенного командой `bot.runner.live`: режим `paper`/`demo`/`live`, капитал, сделки, события (как раньше) |

Вкладка обновляется сама каждые 10 секунд.

### Вкладка «Данные»

- **Новая монета** — введите `SOL` или `SOLUSDT` и нажмите **Добавить**. Интерфейс проверит на Bybit, что бессрочный USDT-контракт существует и торгуется, возьмёт с биржи шаг цены, шаг и минимум объёма и сохранит в `config\symbols.local.yaml` (проскальзывание для бэктеста — 0,1%; можно поправить в файле). Монета сразу появится во всех списках. **Убрать** можно только добавленные так монеты; скачанные свечи остаются.
- Таблица монет показывает, с какого и по какое время скачаны минутные свечи (UTC).
- **Загрузить историю с Bybit** — отметьте монеты, укажите период и нажмите **Загрузить**. Догружаются только пропуски: если раньше скачались только свежие дни, старая история догрузится; повторный запуск ничего не качает заново. Ход загрузки виден под кнопкой.

### Вкладка «Журналы»

Список файлов `logs\journal\*.jsonl`: журнал каждого paper-бота, бота из терминала (`paper.jsonl`, `demo.jsonl`) и список запусков бэктестов (`backtests.jsonl`). Клик — последние 300 записей, «скачать» — весь файл. Что в них записано и как дать их ИИ на проверку — `docs\LOGS.md`.

### Вкладка «Команды»

Слева — все команды терминала по группам (проверка, данные, исследования, Telegram, бот), справа — поля параметров (`*` — обязательные; рядом — флаг командной строки). **Запустить** выполняет ту же команду, что в терминале, вывод появляется ниже. **Остановить** прерывает команду. Внизу — последние запуски; клик по строке показывает их вывод. Весь вывод также сохраняется в `logs\jobs\`.

Две вещи — только в терминале: реальный счёт (`--mode live` требует ручного подтверждения) и ручная разметка постов (`llm_parser --label` задаёт вопросы). Первый вход в Telegram (`telegram_reader`) спрашивает код — его нужно один раз ввести в терминале.

### Почему график догружает свечи сам

График рисуется из файлов `data\klines`. При открытии живого графика интерфейс сам докачивает недостающие минутные свечи с Bybit (без ключей, в фоне) — в статусе «догружаю свежие свечи с Bybit…». Показывается текущая незакрытая свеча (стратегии её не видят — они работают только с закрытыми). Задержка до 1–2 минут нормальна.

## Часть 6. Бэктесты: как запускать и как читать результат

### Что такое бэктест здесь

Стратегия «торгует» на исторических свечах по тем же правилам, что и в реальной торговле:

- решение принимается только по **закрытой** свече, вход — по цене открытия **следующей**;
- учитываются комиссия (0,055%), проскальзывание (0,03% BTC, 0,05% ETH; на стопе ×2) и funding;
- размер позиции — риск 0,5% капитала на сделку, плечо не выше 3x;
- те же проверки риска, что у живого бота (стоп 0,5–4 ATR, R:R, издержки и т. д.);
- стартовый капитал 10 000 USDT.

### Стратегии

| Имя | Идея | Главные параметры |
|-----|------|-------------------|
| `trend_following` | Торговля по тренду: EMA50 выше EMA200 и откат к EMA20 → лонг (шорт зеркально). Стоп 2 ATR, выход по трейлинг-стопу. Опции только для бэктеста (живой бот с ними не запустится): `entry=limit` — вход лимитным ордером (комиссия maker), `funding_max` — не входить в сторону, которая платит funding выше порога | `ema_fast`=20, `ema_mid`=50, `ema_slow`=200, `stop_atr`=2.0, `trail_atr`=3.0, `allow_short`, `entry`=market, `limit_offset_atr`=0, `funding_max`=0 (выключен) |
| `time_series_momentum` | Дневной импульс, для таймфрейма 1d: закрытие выше максимума 55 свечей → лонг (шорт зеркально). Стоп 2 ATR(20), выход по минимуму 20 свечей | `entry_length`=55, `exit_length`=20, `stop_atr`=2.0, `allow_short` |
| `mean_reversion` | Возврат к среднему в боковике: ADX < 20, цена за полосой Боллинджера и RSI < 30 → лонг. Тейк — средняя линия, выход по времени через 24 свечи | `bb_std`=2.0, `rsi_low`=30, `rsi_high`=70, `adx_max`=20, `stop_atr`=1.5, `time_stop_bars`=24 |
| `composite` | Переключает стратегии по режиму рынка: в боковике mean_reversion, в тренде trend_following | `mode`=regime (или all — без учёта режима) |
| `random_entry` | Случайные входы. Нужна только для сравнения: стратегия должна быть заметно лучше случая | `probability`, `stop_atr`, `tp_atr`, `seed` |

### Способ 1. Бэктест из интерфейса

Вкладка нужной стратегии (например, **Trend Following**) → над графиком выберите символ и таймфрейм → снизу вкладка **Бэктест** → период и параметры → **Запустить бэктест**. Недостающие данные за период загрузятся сами. Результат откроется на графике, во вкладках «Сделки», «Капитал», «Отчёт» (Часть 5).

### Способ 2. Бэктест командой

```powershell
uv run python -m bot.backtest.report --strategy trend_following --symbol BTCUSDT --timeframe 4h --from 2021-01-01 --to 2024-06-30
```

С изменёнными параметрами — `--param имя=значение`, можно несколько раз:

```powershell
uv run python -m bot.backtest.report --strategy mean_reversion --symbol ETHUSDT --timeframe 15m --from 2021-01-01 --to 2024-06-30 --param bb_std=2.5 --param adx_max=25
```

Результат сохраняется в папку `data\backtests\<дата-время>_<стратегия>_<символ>_<таймфрейм>\`:

| Файл | Что внутри |
|------|-----------|
| `report.md` | Отчёт (то же, что во вкладке «Отчёт») |
| `trades.csv` | Все сделки — можно открыть в Excel |
| `equity.csv` | Капитал после каждой свечи |

Обновите страницу интерфейса (`F5`) — бэктест появится в списке «Бэктест».

### Как читать отчёт

| Метрика | Что значит | Ориентир |
|---------|-----------|---------|
| Сделок | Сколько сделок за период | ≥ 100, иначе вывод ненадёжен |
| Win Rate | Доля прибыльных | смотреть вместе со средним выигрышем/проигрышем |
| Profit Factor (PF) | Сумма прибылей / сумма убытков | > 1,2 после всех издержек |
| Expectancy | Средний результат сделки в R (R = риск на сделку) | > 0,1R |
| Доходность / годовых | Итог за период | сравнить с buy & hold |
| Max Drawdown | Самое большое падение капитала от пика | чем меньше, тем лучше |
| Sharpe / Sortino | Доходность с поправкой на колебания | > 1 на новых данных |
| Комиссии / проскальзывание / funding | Сколько съели издержки | доля в валовой прибыли < 30–40% |
| По годам | Результат каждого года | плохо, если вся прибыль — один год |
| Сделки для ручной проверки | 5 случайных сделок с пошаговым расчётом | пересчитайте одну на калькуляторе и сверьте цены с графиком Bybit |

### Способ 3. Эксперимент: стратегия против случайных входов

Это главный способ понять, есть ли у стратегии преимущество:

```powershell
uv run python -m bot.research.experiment --strategy trend_following --symbol BTCUSDT --timeframe 1h
```

Что делает:
1. Бэктест на in-sample (2021-01-01 … 2024-06-30).
2. Проверка «заглядывания в будущее» — не подсматривает ли стратегия в будущие свечи.
3. 200 прогонов случайных входов с тем же риском, стопами и временем удержания.
4. Сравнение с покупкой и удержанием (buy & hold).
5. Запись в журнал `research\experiments.md` с номером EXP-001, EXP-002…

В отчёте смотрите строку «PF стратегии … лучше N% случайных прогонов». Предварительный вердикт «кандидат» — только если ≥ 100 сделок, PF > 1,2, лучше 95% случайных и нет заглядывания в будущее.

Варианты:

```powershell
# все 3 стратегии × таймфреймы 5m, 15m, 1h × оба символа (долго)
uv run python -m bot.research.experiment --all

# перебор параметров: до 3 параметров и до 100 вариантов
uv run python -m bot.research.experiment --strategy mean_reversion --symbol BTCUSDT --grid adx_max=15,20,25 --grid bb_std=2,2.5

# больше прогонов случайных входов для точности
uv run python -m bot.research.experiment --strategy trend_following --symbol ETHUSDT --runs 1000
```

При переборе (`--grid`) смотрите на тепловую карту в отчёте: хорошие параметры лежат на «плато» — соседние значения тоже дают хороший результат. Одиночный яркий пик — это, скорее всего, случайность.

## Часть 7. Проверка на новых данных

История разделена на три периода:

| Период | Даты | Для чего |
|--------|------|----------|
| In-sample | 2021-01-01 — 2024-06-30 | придумывать и настраивать стратегии |
| Validation | 2024-07-01 — 2025-06-30 | проверить на данных, которых стратегия «не видела» |
| Hold-out | 2025-07-01 — 2026-09-30 | **один раз**, в самом конце |

### Шаг 7.1. Validation

```powershell
uv run python -m bot.research.validate --strategy trend_following --symbol BTCUSDT --timeframe 4h --stage validation
```

Отчёт `validation.md` в `data\backtests\...validation-...\`: метрики in-sample и validation рядом, проверка на втором символе, критерии (PF > 1,1; Expectancy > 0; просадка не больше 1,5 × in-sample; ≥ 30 сделок), Монте-Карло просадки.

### Шаг 7.2. Walk-forward

Обучение на 12 месяцах → проверка на следующих 3 → сдвиг на 3 месяца, и так по всей истории до hold-out. Параметры на каждом шаге выбираются заново.

```powershell
uv run python -m bot.research.validate --strategy trend_following --symbol BTCUSDT --timeframe 4h --stage walk-forward --grid stop_atr=2,3
```

### Шаг 7.3. Hold-out — один раз

```powershell
uv run python -m bot.research.validate --strategy trend_following --symbol BTCUSDT --timeframe 4h --stage holdout --param stop_atr=2
```

Запуск записывается в `research\holdout-log.md`. Второй раз для той же стратегии, символа и таймфрейма бот откажется (иначе hold-out превращается в ещё одну подгонку). После hold-out стратегию по его итогам не меняют.

### Шаг 7.4. Автоматический перебор (конвейер)

```powershell
uv run python -m bot.research.pipeline --dry-run   # сколько вариантов будет проверено
uv run python -m bot.research.pipeline             # запуск
```

Проходит все комбинации из `config/research.yaml` через walk-forward и для каждой считает **DSR** (Deflated Sharpe Ratio) — вероятность, что результат не случаен, с учётом того, сколько всего вариантов перебрали за всё время. Число попыток хранится в `research\trials.json` — **не удаляйте этот файл**. Кандидат — DSR ≥ 0,95 и выполнены критерии из 7.1; его затем проверяют hold-out (7.3).

### Порядок работы

1. Идея → эксперимент (Часть 6, способ 3). Не лучше случайных — отложить.
2. Validation и walk-forward.
3. Hold-out один раз.
4. Прошло — paper, затем демо (Часть 9) с теми же параметрами.

## Часть 8. ИИ: ML-фильтр и Telegram-канал

### ML-фильтр сигналов

Модель учится на сделках стратегии в in-sample и оценивает вероятность, что новая сделка будет прибыльной. Фильтр может только **пропустить** сигнал, но не создаёт сделки и не меняет стоп или объём.

```powershell
uv run python -m bot.research.ml_filter --strategy mean_reversion --symbol BTCUSDT --timeframe 1h
```

Модель сохраняется в `data\models\mean_reversion_BTCUSDT_1h.joblib`, отчёт — в `data\backtests\...mlfilter-...\validation.md`. Итог «фильтр полезен» — только если на validation он оставил ≥ 50% сделок, улучшил Expectancy или просадку и был лучше 95% случайных отборов. Только тогда в `config/live.yaml` можно поставить `ml_filter: true`.

### Telegram-канал + Claude

Нужны ключи из шагов 2.4 и 2.5.

```powershell
# 1. Скачать посты канала (впервые спросит номер телефона и код из Telegram)
uv run python -m bot.analyzer.telegram_reader --channel имя_канала_без_@

# 2. Вручную разметить 30 постов (бот покажет пост и спросит ваше мнение)
uv run python -m bot.analyzer.llm_parser --label 30

# 3. Разобрать новые посты через Claude
uv run python -m bot.analyzer.llm_parser --parse --limit 20

# 4. Насколько ИИ совпадает с вашей разметкой
uv run python -m bot.analyzer.llm_parser --compare

# 5. Помогают ли мнения канала: движение цены после постов против случайных моментов
uv run python -m bot.research.channel_study --symbol BTCUSDT
```

Дешевле разбирать моделью `--model claude-haiku-5-5`. Посты и разбор видны во вкладке **Telegram**. Папку `data\telegram\` (сессия вашего аккаунта) никому не передавайте.

## Часть 9. Торговля: paper и демо-счёт

### Шаг 9.1. Выбрать стратегии: `config/live.yaml`

Откройте `config/live.yaml` в VS Code:

```yaml
mode: paper
paper_capital: 10000
reconcile_minutes: 1
close_unknown: false
unknown_stop_pct: 0.02
history_days: 30
instances:
  - strategy: trend_following
    symbol: BTCUSDT
    timeframe: 4h
    params: {}
    ml_filter: false
```

Чтобы торговать несколько стратегий — добавьте блоки в `instances`, например:

```yaml
instances:
  - strategy: trend_following
    symbol: BTCUSDT
    timeframe: 4h
    params: {stop_atr: 2.0}
    ml_filter: false
  - strategy: mean_reversion
    symbol: ETHUSDT
    timeframe: 15m
    params: {}
    ml_filter: false
```

Используйте те стратегии и параметры, которые прошли Часть 7. Отступы (пробелы) в YAML важны — копируйте как в примере.

### Шаг 9.2. Paper — виртуальная торговля по живым ценам

Ключи не нужны.

```powershell
uv run python -m bot.runner.live --mode paper
```

Что происходит:

1. Бот докачивает пропущенные свечи и сверяет своё состояние.
2. Пишет `Бот работает в режиме paper`.
3. Каждую минуту получает закрытую свечу. На закрытии свечи таймфрейма стратегии (например, раз в час для 1h) вызывает стратегию.
4. Сигнал проходит 13 проверок риска. Если всё в порядке — бот считает объём и «открывает» сделку со стопом и тейком.
5. Стоп и тейк проверяются каждую минуту по тем же правилам, что в бэктесте.

Всё записывается в `data\bot.sqlite` и видно во вкладке **Бот** (режим `paper`). После перезапуска бот продолжит с того же места, включая виртуальный капитал.

Окно терминала с ботом должно оставаться открытым. Компьютер не должен засыпать: Параметры Windows → Система → Питание → «Переводить в спящий режим» — «Никогда».

### Шаг 9.3. Демо — настоящие ордера на демо-счёте Bybit

Нужны ключи из шага 2.2. Убедитесь, что `check_connection.py` показывает баланс.

```powershell
uv run python -m bot.runner.live --mode demo
```

Отличия от paper:

- ордера уходят на демо-счёт Bybit, их видно в приложении Bybit (в демо-режиме);
- **стоп и тейк ставятся на бирже вместе с ордером** — позиция защищена, даже если компьютер выключится;
- плечо 3x, маржа считается от реального баланса демо-счёта;
- раз в минуту бот сверяется с биржей: позиции без стопа сразу получают стоп; позиция, закрытая стопом, отмечается закрытой; чужая позиция (открытая вручную) — предупреждение и аварийный стоп 2%;
- при обрыве интернета бот не открывает новых сделок, присылает одно сообщение «нет связи» и продолжает после восстановления.

**Остановка бота `Ctrl+C` не закрывает позиции** — они остаются на бирже со стопами. Закрыть всё — аварийная остановка (Часть 10).

### Шаг 9.4. Telegram-команды

Если заполнены `TG_BOT_TOKEN` и `TG_CHAT_ID`, бот присылает сообщения о запуске, входах, выходах, паузах, сбоях связи и аварийной остановке.

| Команда | Что делает |
|---------|-----------|
| `/status` | Режим, капитал, остановка/пауза, открытые позиции с результатом |
| `/kill` | Аварийная остановка — сразу |
| `/resume` | Возобновить после остановки или паузы |

### Шаг 9.5. Почему бот не открывает сделки

Это нормально: хорошие сигналы редки, а проверки строгие. Откройте вкладку **Бот → События** и найдите строки `risk … отклонён: N: причина`:

| Номер | Что не прошло |
|-------|---------------|
| 1 | Стоп с неправильной стороны |
| 2 | Отношение прибыли к риску (R:R) меньше 1,5 (для mean_reversion — 1,0) |
| 3 | Стоп ближе 0,5 ATR или дальше 4 ATR |
| 4 | Стоп слишком близко к цене ликвидации |
| 5 | По этому сигналу позиция уже есть (повтор) |
| 6 | Уже открыто 2 позиции или уже есть позиция по этому символу |
| 7 | Суммарный риск открытых позиций больше 1,5% капитала |
| 12 | Комиссии и проскальзывание больше 20% ожидаемой прибыли |
| 13 | Данные устарели (нет свежих свечей) |

Плюс паузы: убыток за день 2% → пауза до следующего дня (по UTC); 6 убытков подряд → пауза; просадка 10% от пика → полная остановка до `/resume`.

### Шаг 9.6. Сравнить бота с бэктестом

Через 2–4 недели работы:

```powershell
uv run python -m bot.research.live_vs_backtest --mode paper
uv run python -m bot.research.live_vs_backtest --mode demo --out data\reports\demo_vs_backtest.md
```

Бэктест той же стратегии на тех же свечах; сделки сопоставляются по одному и тому же идентификатору сигнала. Смотрите: доля совпавших сигналов (должна быть высокой), разница цены входа в базисных пунктах (1 б.п. = 0,01%), совпадение причин выхода. Большие расхождения — повод искать ошибку, а не подгонять параметры.

### Шаг 9.7. Когда демо-этап считается пройденным

- ≥ 4 недель на демо и ≥ 30 сделок без нарушений правил риска;
- сравнение с бэктестом без необъяснённых расхождений;
- пройдены ручные тесты сбоев:

| # | Что сделать | Что должно быть |
|---|-------------|-----------------|
| 1 | При открытой позиции выключить интернет на 5 минут | Одно сообщение «нет связи»; стоп виден на Bybit; после включения — «связь восстановлена» |
| 2 | `Ctrl+C` сразу после сообщения о входе, запустить снова | Второй позиции нет, сделка в статусе `open` |
| 3 | Перезапустить бот при открытой позиции | Позиция и стоп на месте, бот продолжает её вести |
| 4 | Перезапуск на той же свече (повтор сигнала) | Второго ордера нет; в событиях «5: позиция по этому сигналу уже есть» |
| 5 | Частичное исполнение | Бот использует фактический объём с биржи |
| 6 | Объём с неверным шагом | Объём округляется вниз до шага биржи |
| 7 | Резкое движение через стоп | Позиция закрыта биржей; цена может быть хуже стопа (проскальзывание) |

Автоматические версии этих тестов запускаются вместе с `uv run pytest`.

## Часть 10. Аварийная остановка

Что делает: отменяет ордера, **закрывает все позиции** рыночными ордерами и запрещает новые сделки до ручного возобновления.

| Способ | Как | Когда срабатывает |
|--------|-----|-------------------|
| Кнопка | Интерфейс → вкладка **Бот** → «Аварийная остановка» → подтвердить | в течение минуты |
| Telegram | `/kill` | сразу |
| Файл | в терминале `New-Item data\KILL` | в течение минуты |
| Автоматически | просадка 10% от пика капитала | сразу |

Возобновить: кнопка «Возобновить» во вкладке **Бот** или `/resume` в Telegram. Файл `data\KILL` бот удалит сам. Возобновление снимает остановку и паузу, обнуляет серию убытков, а пиком капитала становится текущий капитал.

## Часть 11. Реальный счёт (выключен)

Код для реального счёта есть, но **выключен тремя замками**, которые открываете только вы:

1. Отдельный файл `.env.live` с ключом **реального** счёта (Read-Write, **без вывода**), `BYBIT_ENV=live` и `ALLOW_LIVE=true`. Файл не попадает в git.
2. Запуск только командой `uv run python -m bot.runner.live --mode live`. В `config/live.yaml` режим live указать нельзя.
3. При запуске бот показывает капитал и просит ввести `LIVE <капитал>` (например, `LIVE 500`).

На реальном счёте действуют строгие лимиты (`live_risk` в `config/default.yaml`): риск 0,25% на сделку, одна позиция, дневной убыток 1% или просадка 5% — **полная остановка** до `/resume`.

Сравнение исполнения реального счёта с демо (бот запущен на обоих с одинаковыми стратегиями):

```powershell
uv run python -m bot.research.live_vs_demo
```

Переходить на реальный счёт — только после шага 9.7 и только с суммой, которую не жалко потерять полностью.

## Часть 14. Частые проблемы

| Что видите | Причина | Что делать |
|-----------|---------|-----------|
| `uv : The term 'uv' is not recognized` | терминал открыт до установки uv | закрыть и открыть терминал (или VS Code целиком) |
| `failed` в `uv run pytest` | что-то не так с установкой или кодом | выполнить `uv sync` ещё раз; если не помогло — прислать вывод |
| График пустой, «нет данных» | история не скачана | Часть 4, шаг 4.1 или 4.2 |
| График «отстаёт на N мин», ошибка догрузки | нет интернета или Bybit недоступен | проверить интернет; запустить `bot.data.downloader` |
| Не видно последних минут | бот хранит только закрытые минутные свечи | нормально, задержка до 1–2 минут |
| `Нет 1m-свечей …` при бэктесте | нет истории за период | скачать историю (Часть 4) |
| `В .env не заданы BYBIT_API_KEY…` | ключи не вписаны или файл не сохранён | Часть 2, шаг 2.2; `Ctrl+S` |
| `10003` / `API key is invalid` | ключ создан не в демо-режиме или опечатка | создать ключ в Demo Trading заново |
| `10002` / ошибка времени | часы компьютера спешат или отстают | синхронизировать часы Windows |
| `10004` / ошибка подписи | неверный `BYBIT_API_SECRET` | скопировать секрет заново (или создать новый ключ) |
| `110007` / недостаточно баланса | на демо-счёте нет денег | пополнить демо-счёт (шаг 2.2, п. 3) |
| Ошибка про поле в `default.yaml` при запуске | значение лимита мягче разрешённого | вернуть прежнее значение |
| Ошибка YAML в `live.yaml` | неверные отступы | сравнить с примером в шаге 9.1 |
| Бот не открывает сделки | сигналы отклоняются проверками риска | вкладка «Бот» → «События», шаг 9.5 |
| Telegram молчит | неверный токен/chat id или вы не писали боту | шаг 2.3; написать боту первым |
| Интерфейс не открывается | порт 8000 занят | в `config/default.yaml` поменять `app.port` на 8001 |
| `Уже идёт другой бэктест` | одновременно — только один бэктест | дождаться окончания |
| `Нет 1m-свечей … за …` при бэктесте | нет истории за период, и загрузить не удалось (нет интернета) | вкладка «Данные» → «Загрузить историю», или галочка «догрузить данные» в форме бэктеста |
| Вопрос про hold-out при бэктесте | период задевает 2025-07-01 … 2026-09-30 | выбрать период раньше или позже; hold-out открывать один раз (Часть 7) |
| `На Bybit нет бессрочного контракта …` | опечатка в имени монеты или у монеты нет USDT-контракта | проверить имя на bybit.com (раздел Derivatives → USDT Perpetual) |
| Paper-бот «ошибка» сразу после создания | не скачалась история (нет интернета) или неверные параметры | текст ошибки — рядом с состоянием; исправить и нажать «Старт» |

Логи: `logs\bot.log` (новый файл каждый день, хранятся 30 дней). События бота: вкладка «Боты» и база `data\bot.sqlite`. Подробные журналы сделок и бэктестов: `logs\journal\` (вкладка «Журналы», `docs\LOGS.md`). Вывод команд и задач интерфейса: `logs\jobs\`.
