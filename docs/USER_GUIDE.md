## 1. Что умеет бот

Работа идёт по этапам из [03-implementation-plan.md](03-implementation-plan.md), и каждый следующий этап опирается на предыдущий:

| Этап | Что делает | Главная команда |
|------|-----------|-----------------|
| 1 | Загружает историю свечей Bybit и принимает живой поток | `bot.data.downloader`, `bot.data.live_feed` |
| 2–3 | Бэктест стратегий с комиссиями, проскальзыванием и funding; сравнение со случайными входами | `bot.backtest.report`, `bot.research.experiment` |
| 4 | Проверка на новых данных: validation, walk-forward, hold-out | `bot.research.validate` |
| 5 | Веб-интерфейс: график, сделки, капитал, запуск бэктеста | `bot.app.api` |
| 6 | Режим рынка, ML-фильтр сигналов, разбор Telegram-канала через Claude API | `bot.research.ml_filter`, `bot.analyzer.*` |
| 7 | Торговля: paper (виртуально) и Bybit Demo, лимиты риска, сверка с биржей, Telegram-уведомления, аварийная остановка | `bot.runner.live` |
| 8 | Реальный счёт с минимальным риском. **Выключен**, включает только владелец | `bot.runner.live --mode live` |
| 9 | Автоматический перебор стратегий с поправкой на число попыток | `bot.research.pipeline` |

Главные правила, которые код соблюдает сам:

- Стратегия видит только закрытые свечи. В бэктесте вход происходит по открытию следующей свечи.
- Стратегии, ML-фильтр и риск-менеджер — один и тот же код для бэктеста, paper и демо. Различается только «брокер».
- Стоп-лосс всегда стоит на бирже, а закрывающие ордера отправляются с флагом `reduceOnly`.
- ИИ (Claude) только читает тексты и ничего не решает о сделках.

## 2. Установка

Это делается один раз.

1. Установить Git: https://git-scm.com/download/win
2. Установить uv, менеджер Python-пакетов. В PowerShell:
   ```powershell
   powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
   ```
   Потом закрыть и снова открыть терминал. Python 3.12 ставить отдельно не нужно, uv скачает его сам.
3. Установить зависимости и проверить, что всё работает:
   ```powershell
   uv sync
   uv run pytest
   ```
   Должно получиться `... passed` без `failed`.

Чтобы обновить код после изменений в репозитории:

```powershell
git pull
uv sync
```

## 3. Настройка

### 3.1 Ключи и пароли: файл `.env`

Скопируйте пример и откройте копию в VS Code:

```powershell
Copy-Item .env.example .env
```

| Переменная | Где взять | Для чего |
|-----------|-----------|----------|
| `BYBIT_API_KEY`, `BYBIT_API_SECRET` | Bybit → Demo Trading → API. Права «чтение + торговля», **без вывода средств** | Баланс и ордера на демо-счёте |
| `BYBIT_ENV` | Оставить `demo` | Режим счёта |
| `ALLOW_LIVE` | Оставить `false` | Защита от реального счёта |
| `ANTHROPIC_API_KEY` | console.anthropic.com → API Keys | Разбор постов Telegram (этап 6) |
| `TG_API_ID`, `TG_API_HASH` | my.telegram.org → API development tools | Чтение Telegram-канала (этап 6) |
| `TG_BOT_TOKEN` | @BotFather в Telegram → `/newbot` | Уведомления и команды бота (этап 7) |
| `TG_CHAT_ID` | Напишите своему боту любое сообщение, затем откройте в браузере `https://api.telegram.org/bot<токен>/getUpdates` и найдите `"chat":{"id":...}` | Куда слать уведомления. Команды принимаются только из этого чата |

Пустые строки разрешены: если ключа нет, соответствующая функция просто выключена.

**Правила безопасности:**

- Файл `.env` не попадает в git. Проверить: `git status` не должен его показывать.
- Ключи не вставляйте в чат, письма и скриншоты.
- Бот не пишет ключи в логи. Можно проверить, что в `logs\bot.log` их нет.

Проверить ключи и связь с биржей (команда ордера не отправляет):

```powershell
uv run python scripts/check_connection.py
```

Должны появиться серверное время, параметры BTCUSDT и ETHUSDT и баланс демо-счёта. Если разница времени больше ±1000 мс, синхронизируйте часы: Параметры Windows → Время и язык → «Синхронизировать сейчас».

### 3.2 Общие настройки: `config/default.yaml`

| Раздел | Что настраивается |
|--------|------------------|
| `data` | Папка данных, символы (`BTCUSDT`, `ETHUSDT`), дата начала истории |
| `app` | Адрес и порт веб-интерфейса (по умолчанию http://127.0.0.1:8000) |
| `costs` | Комиссии (taker 0,055%, maker 0,02%), проскальзывание по символам, стартовый капитал бэктеста |
| `instruments` | Шаг цены, шаг объёма и минимальный объём. Сверьте с выводом `check_connection.py` |
| `risk` | Риск на сделку 0,5% и плечо до 3x |
| `limits` | 13 проверок перед каждой сделкой из [05-risk-and-execution.md](05-risk-and-execution.md) |
| `live_risk` | Профиль риска реального счёта (этап 8) |

Лимиты в `risk`, `limits` и `live_risk` можно только ужесточать. Если вписать значение мягче, чем в [05](05-risk-and-execution.md), бот не запустится и напишет, какое поле неверно. Ослабить лимит можно только сознательным решением с правкой кода.

Основные лимиты:

| Проверка | Значение |
|----------|----------|
| Открытых позиций одновременно | не больше 2, по одному символу — 1 |
| Суммарный риск открытых позиций | не больше 1,5% капитала |
| BTC и ETH в одну сторону | риск второй позиции делится на 1,5 |
| Дневной убыток | 2%: пауза до следующего дня (UTC) |
| Просадка от пика | 10%: полная остановка до ручного `/resume` |
| Убытков подряд | 6: пауза до следующего дня |
| Стоп | от 0,5 до 4 ATR от входа |
| Минимальный R:R | 1,5 (для mean_reversion — 1,0) |
| Издержки | меньше 20% потенциальной прибыли |
| Свежесть данных | последняя свеча не старше 2 интервалов |

### 3.3 Какие стратегии торгует бот: `config/live.yaml`

```yaml
mode: paper            # paper — виртуально, demo — Bybit Demo Trading
paper_capital: 10000   # стартовый капитал paper
reconcile_minutes: 1   # как часто сверяться с биржей
close_unknown: false   # чужую позицию: false — предупредить и поставить стоп, true — закрыть
unknown_stop_pct: 0.02 # аварийный стоп для чужой позиции без стопа (2% от входа)
history_days: 30       # сколько дней истории брать для индикаторов
instances:
  - strategy: breakout
    symbol: BTCUSDT
    timeframe: 1h
    params: {}         # параметры как в бэктесте, например {bb_std: 2.5}
    ml_filter: false   # true — ML-фильтр из data/models (только если он признан полезным)
```

Можно указать несколько стратегий. Лимит «одна позиция на символ» действует на все сразу.

Доступные стратегии: `mean_reversion`, `trend_following`, `breakout`, `composite` (переключается по режиму рынка) и `random_entry` (случайные входы, нужна только для сравнения). Список параметров со значениями по умолчанию видно на вкладке «Запуск» в интерфейсе.

### 3.4 Что перебирает конвейер исследований: `config/research.yaml`

Здесь задаются символы, таймфреймы и сетка параметров для каждой стратегии (подробнее в разделе 6.5).

## 4. Данные: загрузка истории

Свечи хранятся в `data\klines\<символ>\1m\` по месяцам (Parquet). Старшие таймфреймы (5m, 15m, 1h, 4h) собираются из 1m на лету.

```powershell
# Вся история с 2021-01-01 по обоим символам: 1m-свечи, funding, open interest
uv run python -m bot.data.downloader

# Только один символ и с определённой даты
uv run python -m bot.data.downloader --symbol BTCUSDT --from 2026-09-01

# Только funding
uv run python -m bot.data.downloader --only funding
```

Загрузку можно прервать и запустить снова: она продолжит с места остановки. Полная история занимает около 3 млн свечей на символ.

Проверить качество данных (пропуски, дубликаты, аномальные свечи):

```powershell
uv run python -m bot.data.quality
```

Отчёт сохраняется в `data\reports\quality_<символ>.md`.

Живой поток закрытых 1m-свечей отдельно от бота нужен только для проверки:

```powershell
uv run python -m bot.data.live_feed --hours 24
```

Перед исследованиями периодически догружайте свежие свечи той же командой `bot.data.downloader`.

## 5. Веб-интерфейс

```powershell
uv run python -m bot.app.api
```

Откройте в браузере http://127.0.0.1:8000. Время на графике — ваше локальное.

| Где | Что |
|-----|-----|
| Шапка | Символ, таймфрейм, выбор бэктеста и сделки. EMA 20/50/200 и полосы Боллинджера |
| Вкладка «Сделки» | Сделки выбранного бэктеста. Клик по строке показывает сделку на графике со входом, стопом и тейком |
| «Капитал» | Кривая капитала бэктеста |
| «Отчёт» | Текст отчёта (метрики, по годам, проверки) |
| «Запуск» | Запуск бэктеста с выбранными параметрами. Период hold-out (с 2025-07-01) отсюда недоступен |
| «Telegram» | Посты канала и их разбор ИИ (только для справки) |
| «Бот» | Состояние живого бота: капитал, пауза или остановка, открытые и закрытые сделки, события. Кнопки «Аварийная остановка» и «Возобновить» |

Интерфейс и бот — отдельные программы. Их можно запускать в двух окнах терминала одновременно.

## 6. Исследование стратегий

Данные разделены на три периода:

| Период | Даты | Для чего |
|--------|------|----------|
| In-sample (IS) | 2021-01-01 — 2024-06-30 | Разработка и подбор параметров |
| Validation | 2024-07-01 — 2025-06-30 | Проверка на новых данных |
| Hold-out | 2025-07-01 — 2026-09-30 | **Один раз**, в самом конце |

Все результаты записываются в журнал `research\experiments.md`, включая неудачные. Отчёты и сделки сохраняются в `data\backtests\<время>_<стратегия>_<символ>_<таймфрейм>\`, и их можно открыть в интерфейсе.

### 6.1 Один бэктест

```powershell
uv run python -m bot.backtest.report --strategy breakout --symbol BTCUSDT --timeframe 1h --from 2021-01-01 --to 2024-06-30
# с параметрами:
uv run python -m bot.backtest.report --strategy mean_reversion --symbol BTCUSDT --timeframe 1h --from 2021-01-01 --to 2024-06-30 --param bb_std=2.5 --param adx_max=25
```

### 6.2 Эксперимент: стратегия против случайных входов (in-sample)

```powershell
uv run python -m bot.research.experiment --strategy trend_following --symbol BTCUSDT --timeframe 1h
# все 3 стратегии × 3 таймфрейма × оба символа:
uv run python -m bot.research.experiment --all
# перебор параметров (не больше 3 параметров и 100 вариантов):
uv run python -m bot.research.experiment --strategy mean_reversion --symbol BTCUSDT --grid adx_max=15,20,25 --grid bb_std=2,2.5
```

Стратегия интересна, только если она заметно лучше случайных входов с тем же риском. В отчёте это поле «лучше N% случайных».

### 6.3 Проверка на новых данных (этап 4)

```powershell
# validation:
uv run python -m bot.research.validate --strategy breakout --symbol BTCUSDT --timeframe 1h --stage validation
# walk-forward (обучение 12 мес., тест 3 мес., шаг 3 мес.) с выбором параметров на каждом окне:
uv run python -m bot.research.validate --strategy breakout --symbol BTCUSDT --timeframe 1h --stage walk-forward --grid volume_mult=1.2,1.5,2
# hold-out — ОДИН раз для окончательно выбранной стратегии и параметров:
uv run python -m bot.research.validate --strategy breakout --symbol BTCUSDT --timeframe 1h --stage holdout --param volume_mult=1.5
```

Критерии вне выборки: PF больше 1,1, Expectancy больше 0, просадка не больше 1,5 × IS и не меньше 30 сделок. Отчёт включает Монте-Карло просадки.

Каждый просмотр hold-out записывается в `research\holdout-log.md`. Второй просмотр той же стратегии на том же символе и таймфрейме бот откажется запускать. После просмотра hold-out стратегию по его итогам больше не меняют.

### 6.4 Порядок работы

1. Гипотеза → эксперимент на IS (6.2). Если стратегия не лучше случайных входов, её откладывают.
2. Validation и walk-forward (6.3). Параметры должны лежать на «плато»: соседние значения дают похожий результат, а не единичный пик.
3. Hold-out один раз.
4. Если всё пройдено: paper, затем демо (раздел 8) с той же стратегией и параметрами.

### 6.5 Автоматический конвейер (этап 9)

```powershell
uv run python -m bot.research.pipeline --dry-run   # сколько попыток будет
uv run python -m bot.research.pipeline             # запуск
```

Конвейер проходит все комбинации из `config/research.yaml` через walk-forward. Каждой комбинации он считает **Deflated Sharpe Ratio (DSR)** — вероятность, что настоящий результат лучше нуля с учётом того, сколько вариантов перебрано. Счётчик попыток накопительный, за все запуски: он хранится в `research\trials.json`.

Кандидатом считается комбинация с DSR не ниже 0,95 и с выполненными критериями из 6.3. Hold-out конвейер не трогает: кандидата проверяют вручную по 6.3.

Каждая новая попытка поднимает планку. Поэтому не добавляйте варианты «на всякий случай» и не удаляйте `trials.json`.

## 7. ИИ: режим рынка, ML-фильтр, Telegram-канал

### 7.1 ML-фильтр сигналов

Модель оценивает вероятность, что сделка закроется в плюс, и пропускает только сигналы выше порога. Обучается на IS, проверяется на validation:

```powershell
uv run python -m bot.research.ml_filter --strategy mean_reversion --symbol BTCUSDT --timeframe 1h
```

Модель сохраняется в `data\models\`. Фильтр признаётся полезным, только если на validation он оставил хотя бы 50% сделок, улучшил Expectancy или просадку и оказался лучше 95% случайных отборов того же числа сделок. Только тогда в `config/live.yaml` можно ставить `ml_filter: true`.

### 7.2 Telegram-канал и Claude

```powershell
# 1. Выгрузить посты (первый раз Telegram спросит номер телефона и код):
uv run python -m bot.analyzer.telegram_reader --channel имя_канала
# 2. Разметить вручную 20–30 постов, чтобы потом проверить ИИ:
uv run python -m bot.analyzer.llm_parser --label 30
# 3. Разобрать новые посты через Claude:
uv run python -m bot.analyzer.llm_parser --parse --limit 20
# 4. Сравнить разбор ИИ с ручной разметкой:
uv run python -m bot.analyzer.llm_parser --compare
# 5. Помогают ли мнения канала (сравнение со случайными моментами):
uv run python -m bot.research.channel_study --symbol BTCUSDT
```

Дешевле разбирать моделью `--model claude-haiku-5-5`. Сессия Telegram хранится в `data\telegram\`: никому не передавайте эту папку.

## 8. Живая торговля: paper и демо

### 8.1 Paper — виртуальные сделки по живым ценам

```powershell
uv run python -m bot.runner.live --mode paper
```

Бот сначала догружает пропущенные свечи, затем сверяется с «биржей» и начинает работать. Как он работает:

- Раз в минуту получает закрытую 1m-свечу. Стоп и тейк проверяются по правилам бэктеста: гэп исполняется по цене открытия, а если в одной свече задеты и стоп, и тейк, считается стоп.
- На закрытии свечи таймфрейма стратегии вызывает стратегию. Если есть сигнал, он проходит все проверки риска, бот рассчитывает объём и открывает сделку со стопом и тейком.
- Для открытой сделки: выход по времени закрывает её рыночным `reduceOnly`-ордером, а трейлинг переносит стоп.
- Сделки, события и состояние риска записываются в `data\bot.sqlite`. После перезапуска бот продолжает с того же места, включая виртуальный капитал.

### 8.2 Демо — Bybit Demo Trading

Проверьте, что в `.env` стоит `BYBIT_ENV=demo` и указаны ключи демо-счёта. Затем:

```powershell
uv run python -m bot.runner.live --mode demo
```

Отличия от paper:

- Ордера уходят на `api-demo.bybit.com`. Стоп и тейк передаются вместе с ордером входа и живут на бирже, поэтому позиция защищена, даже если бот или интернет упадут.
- Плечо ставится 3x.
- Сверка с биржей идёт каждую минуту:
  - позиция без стопа сразу получает стоп;
  - позиция, закрытая стопом на бирже, отмечается закрытой;
  - чужая позиция вызывает предупреждение и получает аварийный стоп.
- При обрыве связи бот пропускает новые сделки (проверка 13), один раз сообщает «нет связи» и после восстановления продолжает. Повторно ордер отправляется только после того, как бот проверил, что первый не дошёл.

### 8.3 Уведомления и команды Telegram

Если в `.env` заданы `TG_BOT_TOKEN` и `TG_CHAT_ID`, бот присылает уведомления о запуске, входах, выходах, паузах, сбоях связи и аварийной остановке. Команды можно писать своему боту:

| Команда | Что делает |
|---------|-----------|
| `/status` | Режим, капитал, пауза или остановка, открытые позиции |
| `/kill` | Аварийная остановка (раздел 9) |
| `/resume` | Возобновить торговлю после остановки или паузы |

Команды из других чатов бот игнорирует.

### 8.4 Сравнение с бэктестом

Через несколько недель работы:

```powershell
uv run python -m bot.research.live_vs_backtest --mode paper
uv run python -m bot.research.live_vs_backtest --mode demo --out data\reports\demo_vs_bt.md
```

Команда прогоняет бэктест тех же стратегий на тех же свечах и сопоставляет сделки по `signal_id`. Она показывает долю совпавших сигналов, разницу цен входа (в б.п., 1 б.п. = 0,01%), совпадение причин выхода и разницу результата.

Большие расхождения означают, что где-то ошибка, и это повод разбираться. Подгонять параметры под них не нужно.

### 8.5 Когда этап 7 считается пройденным

- На демо прошло не меньше 4 недель и 30 сделок, нарушений правил риска не было.
- Сравнение с бэктестом не показывает необъяснённых расхождений.
- Пройдены ручные тесты сбоев на демо (ниже).

### 8.6 Ручные тесты сбоев на демо (docs/05)

Автоматические версии этих тестов — в `tests/test_failures.py`, их запускает `uv run pytest`. На демо их стоит повторить вручную:

| # | Что сделать | Что должно быть |
|---|------------|-----------------|
| 1 | При открытой позиции отключить интернет на 5 минут | Одно уведомление «нет связи». Стоп виден на Bybit. После включения — «связь восстановлена», и если стоп сработал, сделка отмечена закрытой |
| 2 | Остановить бот (`Ctrl+C`) сразу после сообщения о входе и запустить снова | Второй позиции нет, сделка в статусе open |
| 3 | Перезапустить бот при открытой позиции | Позиция и стоп на месте, бот продолжает её вести |
| 4 | Тот же сигнал дважды (перезапуск на той же свече) | Второго ордера нет, в событиях — «5: позиция по этому сигналу уже есть» |
| 5 | Частичное исполнение | Бот использует фактический объём позиции с биржи |
| 6 | Объём с неверным шагом | Бот округляет объём вниз до шага биржи |
| 7 | Резкое движение через стоп | Позиция закрыта биржей. Цена может быть хуже стопа, это и есть проскальзывание |

Остановка бота через `Ctrl+C` **не закрывает позиции**: они остаются на бирже со стопами. Чтобы закрыть всё, используйте аварийную остановку.

## 9. Аварийная остановка

Аварийная остановка отменяет ордера, закрывает все позиции рыночными `reduceOnly`-ордерами и запрещает новые сделки до ручного возобновления. Запустить её можно четырьмя способами:

1. Кнопка «Аварийная остановка» на вкладке «Бот» в интерфейсе.
2. Команда `/kill` в Telegram.
3. Создать файл `data\KILL`, например так: `New-Item data\KILL`.
4. Автоматически: при просадке 10% от пика.

Команда `/kill` срабатывает сразу, кнопка и файл — в течение минуты. Возобновить можно кнопкой «Возобновить» или командой `/resume`; файл `data\KILL` бот при этом удалит сам. Возобновление снимает остановку, паузу и серию убытков, а пик капитала становится равным текущему капиталу.

## 10. Реальный счёт (выключен)

Код этапа 8 написан, но выключен тремя замками. Все три открывает только владелец:

1. Отдельный файл `.env.live` с ключом **реального** счёта (права «чтение + торговля», без вывода), `BYBIT_ENV=live` и `ALLOW_LIVE=true`. Файл не попадает в git.
2. Запуск только командой `uv run python -m bot.runner.live --mode live`. В `config/live.yaml` режим live указать нельзя.
3. При старте бот показывает капитал с биржи и просит ввести `LIVE <капитал>`, например `LIVE 500`.

На реальном счёте действует строгий профиль `live_risk`:

- риск 0,25% на сделку;
- одна позиция;
- дневной убыток 1% и просадка 5% вызывают **полную остановку**, а не паузу.

Сравнение исполнения с демо (бот запускается на обоих счетах с одинаковыми стратегиями):

```powershell
uv run python -m bot.research.live_vs_demo
```

Переходить к реальному счёту стоит только после пункта 8.5, и только с суммой, которую не жалко потерять полностью. Этап 8 считается пройденным после 3 месяцев без нарушений правил риска.

## 11. Если что-то не работает

| Симптом | Что делать |
|---------|-----------|
| `uv` не найден | Закрыть и открыть терминал после установки uv |
| `Нет 1m-свечей…` | Загрузить историю (раздел 4) |
| `В .env не заданы BYBIT_API_KEY…` | Заполнить `.env` (3.1) |
| Ошибка про поле в `default.yaml` при запуске | Значение лимита мягче разрешённого. Вернуть прежнее |
| `10002` или ошибка времени от Bybit | Синхронизировать часы Windows |
| `110007` / «недостаточно баланса» | Пополнить демо-счёт в Bybit (Demo Trading → «Пополнить») |
| В событиях часто «отклонён: 13: данные устарели» | Проверить интернет и что бот получает свечи. После долгого простоя это нормально для первых минут |
| Бот не открывает сделки | Посмотреть на вкладке «Бот» строки `risk` в событиях: там указан номер проверки и причина |
| Telegram молчит | Проверить `TG_BOT_TOKEN` и `TG_CHAT_ID` и что вы писали боту первым |
| Интерфейс не открывается | Порт занят: поменять `app.port` в `config/default.yaml` |

Логи лежат в `logs\bot.log` (по дням, хранятся 30 дней). События живого бота видны на вкладке «Бот» и записываются в `data\bot.sqlite`.
