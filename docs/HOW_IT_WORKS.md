# Как работает бот: от поста в Telegram до сделки

Бот торгует только по сценариям автора Telegram-канала (`scenarios.channel` в `config/default.yaml`).
Других стратегий больше нет. `random_entry` осталась только для исследований: с ней сравнивают
результат сценариев («лучше ли это случайных входов»), торговать ею не нужно.

## Коротко

```
пост в канале → выгрузка в базу → разбор в ячейки → бот на закрытии свечи проверяет условие
→ риск-менеджер считает объём → рыночный вход со стопом и тейком на бирже → выход по стопу/тейку
```

Заранее никаких ордеров на биржу не ставится. Условие входа проверяет компьютер, на котором запущен бот.

## 1. Посты

- Посты читает `python -m bot.analyzer.telegram_reader` (Telethon, вход как пользователь Telegram).
  Они сохраняются в `data/bot.sqlite` (таблица `telegram_posts`), картинки — в `data/telegram/media/`.
- Бот сам канал не читает. Выгрузку запускают кнопками на вкладке «Старт»: «Скачать новые посты» (один раз)
  или «Следить за каналом» (каждые 10 минут, пока открыт веб-интерфейс). В терминале то же самое —
  `uv run python -m bot.analyzer.telegram_reader --every 10`.
- Первый вход в Telegram спрашивает номер и код из приложения, поэтому первый раз команду нужно запустить
  в терминале. Сессия сохраняется в `data/telegram.session`, дальше кнопки работают без вопросов.

## 2. Разбор постов в ячейки

- **Ячейка** — один сценарий автора: монета, сторона (LONG/SHORT), условие входа, стоп и цели.
  Условия: закрытие выше/ниже уровня, ретест уровня, касание зоны, «входить сразу».
- Разбор — отдельный шаг, сам он не запускается:
  - «Старт» → «Разобрать через Claude API» (платно, нужен `ANTHROPIC_API_KEY`),
    в терминале `uv run python -m bot.scenarios parse`;
  - или бесплатно в Claude Code: «разбери новые посты» (скилл `telegram-scenarios`).
- ИИ только переносит в таблицу то, что написал автор, с дословными цитатами. Проверяет код: монета
  из белого списка `scenarios.symbols`, стоп и цели с правильной стороны, цитаты есть в тексте поста.
- Посты разбираются по порядку. Новый пост может обновить ячейку (новая версия) или отменить её.
- Если уровни взяты только с картинки, ячейка помечается «уровни с картинки» и не торгуется, пока вы
  не сверите их и не нажмёте «Одобрить» на вкладке «Сценарии».
- Скриншоты прибыли/убытка не анализируются.

## 3. Что делает бот, когда запущен

Бот — это процесс, который получает минутные свечи с Bybit (`LiveFeed`). На каждой новой закрытой
минутной свече:

1. paper: проверяет, не задеты ли стоп или тейк открытой виртуальной сделки, начисляет funding;
2. проверяет аварийную остановку (файл `data/KILL`, кнопка в интерфейсе, команда в Telegram);
3. раз в минуту сверяет свои записи с биржей (`reconcile`);
4. если вместе с этой минутой закрылась свеча таймфрейма бота (по умолчанию 1h):
   - есть открытая сделка по этой монете — только сопровождает её;
   - нет сделки — стратегия заново читает ячейки из базы и смотрит, выполнилось ли условие
     какой-то ячейки **на только что закрытой свече**.

Отсюда:

- новые ячейки подхватываются сами, перезапуск не нужен, но не раньше чем через 5 минут после поста
  (`latency_minutes`) и не раньше закрытия следующей свечи таймфрейма;
- ячейка срабатывает один раз. До срабатывания она «умирает», если цена дошла до стопа автора
  (сценарий отменён рынком) или до первой цели (движение упущено);
- пока по монете открыта сделка, новые срабатывания по этой монете пропускаются;
- если в момент срабатывания бот был выключен, вход пропущен — догонять его бот не будет;
- бот читает последние `history_days` дней свечей (`config/live.yaml`, у paper-ботов интерфейса — 30).
  Пост старше этого окна не торгуется: по такой истории нельзя проверить, что он ещё не сработал.

## 4. Как появляется ордер

Когда условие выполнилось:

1. Стоп и цель: от автора, а если он их не назвал — по умолчанию (`scenarios/levels.py`): стоп 0,5 ATR
   за уровнем входа, для «входить сразу» — 1,5 ATR; цель — первая цель автора с R:R ≥ 2, без целей — 2R.
   Если все цели автора ближе 2R, сделки нет.
2. Риск-менеджер (`risk/limits.py`) проверяет лимиты из `docs/05-risk-and-execution.md` и считает объём
   так, чтобы стоп стоил 0,5% капитала.
3. Отправляется **рыночный** ордер. В нём сразу стоят стоп-лосс и тейк-профит, они живут на стороне биржи.
   `orderLinkId` = id сигнала, поэтому повторная отправка не создаст второй ордер.
4. Дальше сделку закрывает биржа по стопу или тейку. Закрытие по команде (аварийная остановка) — рыночный
   ордер `reduceOnly`.

Лимитных ордеров «заранее по уровню из поста» нет. Это значит, что вход происходит по цене после
закрытия свечи, а не точно по уровню автора.

## 5. Paper, демо и реальный счёт

| | Paper | Демо (Bybit Demo Trading) | Реальный счёт |
|---|---|---|---|
| Где запускается | вкладка «Старт» или «Боты» в веб-интерфейсе (или `bot.runner.live --mode paper`) | только терминал: `uv run python -m bot.runner.live --mode demo` | выключен, три замка (см. USER_GUIDE, часть 11) |
| Куда уходит ордер | никуда, сделка виртуальная | на демо-счёт Bybit, видно на сайте в Demo Trading | на реальный счёт |
| Цена входа | последняя цена + проскальзывание из настроек | цена биржи | цена биржи |
| Стоп и тейк | проверяются ботом по каждой минуте | стоят на бирже | стоят на бирже |
| Если компьютер выключен | ничего не происходит | открытая сделка защищена стопом на бирже, новых входов нет | так же, как демо |

Стратегия, риск-менеджер и проверки одни и те же во всех режимах и в бэктесте. Отличается только брокер.

Монеты и таймфрейм для бота из терминала задаются в `config/live.yaml` (по умолчанию BTCUSDT и ETHUSDT, 1h).
Ключи демо-счёта — в `.env`.

## 6. Где что смотреть

- Ячейки и посты — вкладка «Сценарии». Активные ячейки также нарисованы линиями на «График и бэктест».
- Сделки и события ботов — вкладка «Боты» (paper-боты и бот из терминала в режиме paper/demo).
- Записи бота — `data/bot.sqlite`, подробный журнал каждого решения — `logs/journal/*.jsonl`
  (вкладка «Журналы», формат в [LOGS.md](LOGS.md)).
- Проверить, сработал бы пост в прошлом, — «Сценарии» → «Бэктест поста».

## Известные ограничения

- Канал и разбор не запускаются сами при старте бота: нужно включить «Следить за каналом»
  и разбирать новые посты (через API или Claude Code).
- Пропущенный вход (бот был выключен, или по монете уже была сделка) не повторяется.
- Вход рыночный по закрытию свечи, а не лимитный по уровню автора.
