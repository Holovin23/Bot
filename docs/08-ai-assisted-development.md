# 08. Разработка с ИИ-ассистентом

Код проекта пишет Claude Code, вы ставите задачи, проверяете результат и принимаете решения. Это рабочая схема, но у неё есть главный риск: **ИИ пишет код, который выглядит правильным и проходит его же тесты, но содержит тонкую ошибку**. В торговом боте такая ошибка либо рисует несуществующую прибыль в бэктесте, либо теряет деньги в живой торговле. Весь процесс ниже построен вокруг этого риска.

## Подготовка (один раз)

1. Установить Python 3.12, Git, VS Code (удобно смотреть код и изменения) и Claude Code.
2. В корне репозитория лежит `CLAUDE.md` — правила проекта, которые ИИ читает в начале каждой сессии. Когда вы замечаете повторяющуюся ошибку ИИ, добавляйте правило туда.
3. Работать в ветках: одна задача — одна ветка — один коммит или pull request. Плохой результат проще выбросить, чем чинить.

## Как ставить задачу

Плохо: «Сделай бэктест».

Хорошо:

```
Задача: этап 2, модель издержек в бэктесте.
Сделай src/bot/backtest/costs.py: функции комиссии (maker/taker), проскальзывания
и funding для позиции. Значения берутся из config/default.yaml.
Требования:
- funding начисляется в 00:00, 08:00, 16:00 UTC по исторической ставке; лонг платит
  при положительной ставке, шорт получает;
- функции чистые, без сети.
Тесты: на каждую функцию, включая пример, посчитанный вручную в комментарии теста.
Не меняй другие файлы. В конце перечисли допущения, которые ты сделал.
```

Правила хорошей задачи:
- **Одна задача — один модуль** или одна функция. Маленький объём проще проверить.
- **Ссылка на документ**: «по разделу Risk Manager из docs/05-risk-and-execution.md».
- **Критерий готовности**: какие тесты, какой вывод, какой график.
- **Явные запреты**: какие файлы не трогать.
- **Просьба перечислить допущения**: там и прячутся ошибки.

## Как проверять результат (без глубокого знания Python)

1. **Запустить тесты самому**: `pytest`. Зелёные тесты — необходимо, но недостаточно.
2. **Посмотреть на числа глазами**: попросить ИИ вывести 5 строк результата и пересчитать одну на калькуляторе.
3. **Посмотреть на график**: каждая сделка бэктеста должна выглядеть на графике так, как вы ожидаете от стратегии. Это главный инструмент проверки для новичка, поэтому интерфейс с графиком (этап 5) идёт рано.
4. **Отдельная сессия-ревьюер**: в новой сессии попросить «найди ошибки в src/bot/backtest/engine.py, особенно заглядывание в будущее, ошибки знака и округления; не исправляй, только перечисли». Свежий взгляд без контекста автора находит больше.
5. **Тест «обрезки данных»** для каждой стратегии: сигналы до даты X не должны меняться, если удалить данные после X. Попросите ИИ написать такой тест один раз и запускать его для всех стратегий.
6. **Если результат слишком хорош** (Profit Factor > 2, Win Rate > 70% на большом числе сделок) — почти наверняка ошибка. Сначала искать ошибку, потом радоваться.

## Чего не доверять ИИ без вашей проверки

- Формулы расчёта объёма позиции и округления под шаг лота.
- Направление (LONG/SHORT) и знаки в расчётах PnL и funding.
- Сдвиги индексов в индикаторах (`shift`, «текущая» или «предыдущая» свеча).
- Всё, что отправляет ордера на биржу, особенно переход с демо на реальный счёт.
- Правки в риск-менеджере: любое ослабление лимита — только с вашего явного решения.

## Порядок работы на один этап

1. Открыть [03-implementation-plan.md](03-implementation-plan.md), взять следующий этап.
2. Попросить ИИ разбить этап на задачи по 1–3 файла и записать их в `docs/tasks/stage-N.md`.
3. Выполнять задачи по одной, проверяя каждую по списку выше.
4. В конце этапа — сессия-ревьюер на весь этап и проверка условия «Готово, когда».
5. Записать в журнал, что сделано и что узнали.

## Полезные приёмы

- Перед сложной задачей попросить ИИ сначала **описать план** и только после вашего «да» писать код.
- Просить объяснить незнакомый код простыми словами: так вы учитесь и замечаете странности.
- Не копить большие изменения: если ИИ правит 10 файлов в одной задаче, задачу нужно было разбить.
- Секреты (`.env`) никогда не вставлять в чат и не коммитить.
