# 03. План реализации

Код пишет ИИ-ассистент, поэтому каждый этап разбит на небольшие задачи, у каждой есть проверяемый результат. Как ставить такие задачи и проверять их выполнение — в [08-ai-assisted-development.md](08-ai-assisted-development.md).

Этапы идут строго по порядку: следующий начинается, когда выполнено условие перехода предыдущего. Интерфейс (этап 5) можно делать параллельно с этапами 3–4.

Ваши варианты C (гибрид: алгоритмы + ИИ-фильтр) и D (исследовательская система, перебирающая стратегии) встроены в план: C — это этап 6, D — этап 9, и он идёт последним, потому что без строгого бэктеста автоматический поиск находит только подгонку под историю.

---

## Этап 0. Фундамент

**Сделать:**
- Репозиторий: `pyproject.toml`, структура папок из [02-architecture.md](02-architecture.md), ruff, mypy, pytest, pre-commit.
- Конфигурация (YAML + `.env`), логирование, модели данных (`Candle`, `Signal`, `Order`, `Position`, `Trade`).
- Аккаунт Bybit Demo Trading, API-ключ демо-счёта, проверка подключения (баланс, серверное время).

**Готово, когда:** `pytest` зелёный, скрипт `check_connection` печатает баланс демо-счёта.

## Этап 1. Market Data

**Сделать:**
- Загрузчик истории свечей (базовый 1m, 5m/15m/1h агрегируются из него), funding, open interest.
- Хранилище Parquet, дозагрузка «с последней свечи».
- Проверка качества: пропуски, дубли, выбросы; отчёт.
- Живой поток: WS-подписка на свечи, отдача только закрытых свечей.

**Готово, когда:** есть ≥ 3 лет данных по BTCUSDT и ETHUSDT; повторный запуск загрузчика ничего не дублирует; живой поток 24 часа пишет свечи без пропусков.

## Этап 2. Бэктест-движок

**Сделать:**
- Событийный движок: проход по закрытым свечам, вызов стратегии, исполнение на **следующей** свече.
- Модель издержек: комиссия maker/taker, funding по фактическим временам и ставкам из истории (обычно раз в 8 часов, но Bybit может менять интервал), проскальзывание (значения в [09-start-checklist.md](09-start-checklist.md)).
- Модель исполнения стопов внутри свечи: если в одной свече задеты и SL, и TP — считать, что сработал SL (пессимистично).
- Метрики и отчёт (см. [04-backtesting-guide.md](04-backtesting-guide.md)).

**Готово, когда:** тесты на синтетических данных дают заранее известный результат; 10 случайных сделок пересчитаны вручную и совпали.

## Этап 3. Базовые стратегии без ИИ (ваш «Этап 1»)

**Сделать:**
- Mean Reversion и Trend Following, затем Breakout.
- Каждую стратегию тестировать на всех трёх таймфреймах (5m, 15m, 1h) как отдельные гипотезы с отдельной записью в журнале. Начинать с 1h: там издержки меньше всего искажают результат.
- Базовые линии для сравнения: buy & hold, случайные входы с тем же стопом/тейком и той же частотой.
- Подбор параметров **только** на периоде разработки (in-sample).

**Готово, когда:** для каждой стратегии есть отчёт: число сделок, Win Rate, Profit Factor, Expectancy, Max Drawdown, доходность после расходов, сравнение с базовыми линиями. Стратегии, которые не лучше случайных входов, отклоняются и записываются в журнал.

## Этап 4. Проверка на новых данных (ваш «Этап 2»)

**Сделать:**
- Разделение истории: in-sample, validation и финальный hold-out (самые свежие данные, открывается **один раз**). Конкретные даты — в [09-start-checklist.md](09-start-checklist.md).
- Walk-forward: скользящее окно «подбор → проверка».
- Устойчивость: тепловая карта параметров (результат не должен держаться на одной «волшебной» точке), Монте-Карло по сделкам, тест на другом инструменте.

**Готово, когда:** стратегия проходит критерии из [01-goals.md](01-goals.md) на OOS и hold-out. Если не проходит ни одна — это результат, а не провал: возвращаемся к гипотезам, а не к подгонке.

## Этап 5. Веб-интерфейс (параллельно с 3–4)

**Сделать по шагам:**
1. FastAPI + страница с графиком Lightweight Charts: свечи, EMA, Bollinger.
2. Маркеры сделок из бэктеста, таблица сделок, кривая капитала.
3. Меню стратегий: выбор, параметры, запуск бэктеста из интерфейса.
4. Позже (этап 7): статус живого бота, открытые позиции, kill switch.
5. Позже (этап 6): лента Telegram-канала с разбором ИИ.

**Готово, когда:** отчёт любого бэктеста можно открыть в браузере и визуально проверить каждую сделку.

## Этап 6. Добавление ИИ (ваш «Этап 3», вариант C)

**Сделать:**
1. Режим рынка правилами (ADX, волатильность) — базовая линия.
2. Разметка сделок методом тройного барьера, признаки на момент сигнала (без будущего).
3. ML-классификатор (логистическая регрессия → LightGBM), кросс-валидация по времени с «очисткой» и эмбарго (purged k-fold).
4. Калибровка вероятностей, график надёжности (reliability diagram), Brier score.
5. Сравнение «стратегия» против «стратегия + фильтр» на OOS.
6. Telegram + Claude API:
   - Telethon выгружает всю доступную историю канала (при 1–2 постах в день за год это ~400–700 постов).
   - Вручную разметить 30–50 постов: эталон для проверки качества разбора.
   - Claude API разбирает архив в JSON по схеме из [02-architecture.md](02-architecture.md); сравнить с ручной разметкой.
   - Проверка пользы: для каждого поста с мнением BULLISH/BEARISH посмотреть движение цены через 4, 24 и 72 часа после публикации; сравнить с движением после случайных моментов времени. Учитывать время публикации точно, а не «день поста».
   - Объём выборки маленький (сотни постов), поэтому вывод «канал помогает» требует заметного и устойчивого эффекта, а не пары удачных месяцев.
   - Если польза есть — `bias` канала становится признаком в ML-фильтре или условием «не торговать против мнения канала». Если нет — лента с разбором остаётся в интерфейсе как справочная информация.
7. Выбор стратегии по режиму рынка (гибрид C) — тоже сравнивается с простой комбинацией всех стратегий.

**Готово, когда:** фильтр улучшает OOS-результат, а не только in-sample. Иначе ИИ остаётся в интерфейсе как «мнение», но не влияет на сделки.

## Этап 7. Paper Trading и Demo (ваш «Этап 4»)

**Сделать:**
- `PaperBroker`: живые данные, виртуальное исполнение — проверка всей цепочки без биржи.
- `BybitBroker` на демо-счёте: ордера с `orderLinkId`, стопы на бирже, обработка ошибок, reconciliation, восстановление после перезапуска.
- Уведомления в Telegram о сделках и ошибках.
- Ежедневное сравнение: что сделал бот против того, что сделал бы бэктест на тех же свечах.

**Готово, когда:** ≥ 4 недель и ≥ 30 сделок; ноль дублей и «потерянных» позиций; тесты сбоев пройдены (выдернуть сеть, убить процесс посреди сделки, перезапустить); расхождение с бэктестом объяснено.

## Этап 8. Минимальный реальный объём (ваш «Этап 5»)

**Сделать:**
- Отдельный ключ реального счёта, суммы, которые не жалко потерять полностью.
- Риск на сделку 0,25%, жёсткий дневной и общий лимит просадки, после срабатывания — только ручной перезапуск.
- Сравнение реального исполнения с демо (проскальзывание, частичные исполнения).

**Готово, когда:** 3 месяца без нарушений правил риска. Только затем обсуждать увеличение объёма.

## Этап 9. Исследовательская система (вариант D)

**Сделать:**
- Конвейер, который перебирает стратегии/параметры/фильтры с автоматическим walk-forward.
- Учёт количества проверенных вариантов: Deflated Sharpe Ratio, поправка на множественные проверки, обязательный финальный hold-out.
- Журнал всех экспериментов, включая неудачные.

**Почему последним:** чем больше вариантов перебрано, тем выше шанс найти «прибыльную» стратегию чисто случайно. Без строгого OOS этот модуль превращается в генератор самообмана.
