# CLAUDE.md

Торговый бот для Bybit Demo Trading. Владелец проекта — новичок в программировании; код пишет ИИ-ассистент, владелец проверяет. Документация: `docs/` (начать с `docs/README.md`).

## Язык

Общение, комментарии к задачам и документация — на русском. Имена в коде — на английском.

## Стек

Python 3.12, asyncio, pybit (Bybit v5), pandas/polars + Parquet, SQLite, FastAPI, TradingView Lightweight Charts, scikit-learn/LightGBM, anthropic SDK, Telethon. Тесты: pytest. Линтеры: ruff, mypy.

## Обязательные правила

- Стратегии, анализатор и риск-менеджер — один и тот же код для бэктеста, paper и демо. Отличается только реализация `Broker`.
- Стратегии работают только с **закрытыми** свечами. Вход в бэктесте — по открытию **следующей** свечи. Никакой нормализации по всему датасету.
- Таймфрейм задаётся в конфиге стратегии (5m, 15m, 1h); базовые данные хранятся в 1m.
- Риск-менеджер — чистые функции без сети и без LLM. Не ослаблять лимиты из `docs/05-risk-and-execution.md` без явного решения владельца.
- LLM (Claude API) только извлекает информацию из текста; не создаёт сделки, не меняет размер и стопы.
- Ордера: `orderLinkId` из `signal_id`, стоп-лосс всегда на стороне биржи, закрывающие ордера `reduceOnly`.
- Бэктест всегда учитывает комиссии, проскальзывание и funding.
- Секреты только в `.env`; никогда не выводить ключи в лог и не коммитить их.
- Реальный (не демо) счёт включается только явным флагом конфигурации, который меняет владелец.

## Как работать над задачей

- Одна задача — небольшое изменение в 1–3 файлах. Если задача больше, предложить разбиение.
- Для каждой новой функции с расчётами — тест с примером, посчитанным вручную.
- В конце ответа перечислить допущения и то, что владельцу стоит проверить глазами.
- Перед коммитом: `ruff check`, `mypy src`, `pytest`.
