# Разбор постов канала в сценарии (план Б)

Ты делаешь ту же работу, что Claude API в плане А: переносишь сценарии автора поста в JSON
по схеме. Правила и схему всегда бери из вывода `pending` — они общие для обоих планов.
Решение о сделке, стоп и цель по умолчанию, объём и лимиты делает код бота, не ты.

## Запрещено

- Придумывать числа, уровни или сценарии, которых нет у автора.
- Анализировать скриншоты с профитом, убытком, позициями, балансом (PNL_SCREENSHOT):
  только отметить их тип.
- Менять код, конфиг или базу напрямую. Ячейки меняются только командой `import`.
- Пропускать посты: они разбираются строго по порядку публикации.

## Разбор новых постов

1. Докачать канал (если владелец не сказал, что уже сделал это):
   `uv run python -m bot.analyzer.telegram_reader`
2. Получить следующий пост: `uv run python -m bot.scenarios pending`
   В JSON: `rules` (правила разбора — следуй им дословно), `schema` (схема ответа),
   `active_cells` (уже сохранённые сценарии), `posts` (один пост: текст, время, картинки).
   Если `posts` пустой — всё разобрано, переходи к шагу 6.
3. Открой каждую картинку из `images` инструментом Read и определи её тип (CHART,
   PNL_SCREENSHOT, OTHER). Уровни бери только с CHART.
4. Запиши ответ по схеме в `data/scenarios/answers/<post_id>.json` (папку создай, если
   её нет). Все поля схемы обязательны; `quotes` — дословные куски текста поста.
5. Примени: `uv run python -m bot.scenarios import data/scenarios/answers/<post_id>.json --post <post_id>`
   Команда покажет, что создано, обновлено, отменено и что отклонено и почему. Если ответ
   не по схеме — исправь файл и повтори один раз. Если сценарий отклонён проверкой
   (нет цитаты, не та сторона стопа) — не подгоняй ответ под проверку, это нормальный итог.
   Затем вернись к шагу 2 (следующий пост видит обновлённые ячейки).
6. Покажи владельцу итог: сколько постов разобрано, какие ячейки созданы, обновлены,
   отменены, что отклонено, и ячейки с уровнями только с картинки — их владелец
   проверяет глазами и одобряет: `uv run python -m bot.scenarios approve <id>`.
   Список активных ячеек: `uv run python -m bot.scenarios list`.

Если владелец просит разобрать только N постов — остановись после N.

## Бэктест одного поста

Владелец даёт текст поста, дату публикации (UTC) и, возможно, картинки.

1. Сохрани текст в `data/scenarios/backtest/post.txt`.
2. Получи правила и схему: `uv run python -m bot.scenarios pending --limit 0`.
3. Разбери пост по правилам (ячеек нет — `existing` пустой) и запиши ответ в
   `data/scenarios/backtest/answer.json`.
4. Запусти:
   `uv run python -m bot.research.scenario_backtest --post data/scenarios/backtest/post.txt --scenario data/scenarios/backtest/answer.json --date "<YYYY-MM-DD HH:MM>"`
   (добавь `--days N`, `--timeframe 15m|1h|4h` или `--allow-image-levels`, если владелец просит).
5. Перескажи результат: сработал ли сценарий и когда, сделка, итог в R, или почему сделки
   не было (стоп автора до входа, риск-менеджер отклонил, цели ближе 2R).
